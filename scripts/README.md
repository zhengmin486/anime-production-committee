# 经济模拟器使用说明

> 历史资料说明：本文记录旧版 V2/V3 契约、旧五阶段制作模型或当时的研究建议，不代表当前目标玩法。现行决策以 [DECISION_LOG.md](DECISION_LOG.md) 为准：项目级公共制作 + 单集六阶段、工作项依赖并行、核心员工每周严格单项目分配、多项目并行及限时资金危机。本文中的旧阶段、资源分配和资金规则仅作为历史证据/旧实现迁移参考，不得直接作为新架构依据。


这是独立于游戏运行时的 Python 蒙特卡洛模型，用于复用现金流口径、比较承制/委员会路线，并测试动态工作量、阶段合格线、工资、加班、外包和非 BD 渠道收入。它不是游戏内核，也不代表所有 V1 机制已经实现。

## 运行

Python 3.10+，无第三方依赖。在仓库根目录执行：

```bash
python scripts/economic_simulator.py
python scripts/economic_simulator.py --config scripts/simulation_config.example.json --out build/economic-sim
python scripts/run_sensitivity.py
python -m unittest discover -s scripts/tests -v
```

默认每种策略运行 500 次；相同代码、配置和 seed 可复现相同结果。输出 `summary.json` 和逐次结果 `trials.csv`。

## V0.6 动态经营策略

默认比较七种策略：原有四种固定基准（全部承制、委员会固定 10% / 50% / 100%）继续保留，新增三种动态策略。动态策略每次只读取市场刷新的 4 个候选企划，以及开工前可见的预算、周期、工作量、目标质量和当前现金；不读取实际商业评分、随机质量结果或未来事件。

| 策略 | 项目选择 | 资金决策 |
|---|---|---|
| 保守经营 | 优先选择单位周期投资压力较低的企划 | 现金达到初始资金 1.5 倍后才考虑委员会，保留较高现金储备，投资比例最高 30% |
| 机会经营 | 按目标质量与预算/工作量的预期机会指标选择 | 保留中等现金储备，委员会投资比例最高 70%，不足 10% 时改为承制 |
| 激进经营 | 优先选择预算与目标质量乘积较高的企划 | 保留较低现金储备，委员会投资比例最高 100%，不足 10% 时改为承制 |

动态策略的现金储备比例、投资上限和项目评分公式只是**模拟器的策略假设**，不属于游戏规则或经济参数，也不应直接移植进游戏。现金储备比例、经营储备周期、委员会启动资金门槛和投资上限集中放在配置文件的 `dynamic_policy` 中，便于审计和调整；本轮不调整工资、外包、收入、周期或其他经济参数。

新增统计包括承制/委员会项目数、每次模拟的平均委员会投资比例、经营过程中的最低现金，以及 BD 收入、承制成功奖励和非 BD 收入的拆分。最低现金用于识别“期末现金尚可，但中途现金流接近断裂”的情况。固定策略作为基准组，动态策略不替代基准组。

## 当前成本与产能假设

- 初始核心员工 4 人，每人每周工资 5 万日元，基础周薪合计 20 万日元。
- 每周固定运营费按 V1 数值提案的 20 万日元计，和工资分开；基础固定现金支出合计 40 万日元/周。
- 内部团队常规产能暂定 70 工作量单位/周；每周产能有 12%随机波动。
- 加班费按正常工资的 1.5 倍计；暂定最多增加常规工时/产能的 20%。模型仅在按剩余工期判断常规产能不足时启用加班。
- 外包按阶段拆分。外包份额代表该阶段工作量由外部团队完成，既增加项目吞吐，也按外包单位价格产生支出：

| 阶段 | 外包工作量占比 | 外包单价（日元/工作量单位） |
|---|---:|---:|
| 脚本 | 20% | 8,000 |
| 分镜 | 25% | 10,000 |
| 原画 | 45% | 14,000 |
| 动画检查 | 30% | 7,000 |
| 后期 | 35% | 9,000 |

## 非 BD 渠道收入假设

非 BD 渠道按合同预算、渠道适配度和商业表现计算毛收入，再按玩家投资比例分配给公司。当前每个委员会项目暂按开放 2 个渠道处理，模拟时从以下渠道中抽取：

| 渠道 | 适配度为 100 时的毛收入基数 |
|---|---:|
| 出版社 | 合同预算 × 25% |
| 玩具 | 合同预算 × 35% |
| 音乐 | 合同预算 × 15% |
| 电视播出 | 合同预算 × 30% |

- 当前普通适配度抽样范围为 20–40；尚未模拟 60–85 的高度匹配项目。
- 商业表现倍率：D 0.3、C 0.6、B 1.0、A 1.5、S 2.5。
- 非 BD 收入是 BD 以外的独立收入，不重复扣除 BD 综合成本；玩家实际取得金额 = 渠道毛收入 × 玩家投资比例。
- 当前“每个项目开放 2 个渠道”是为了试跑的简化假设；正式游戏仍应由委员会成员选择决定具体开放渠道。

## 现有制作模型

- 每种项目类型使用标准工作量与标准周期；每个项目实际工作量围绕基础值随机变化。
- 五阶段按脚本 10%、分镜 15%、原画 35%、动画检查 25%、后期 15%分配工作量。
- 每阶段合格线动态抽样，位于阶段工作量的 65%–80%；达到合格线即可进入下一阶段。
- 每阶段有 35%概率选择额外打磨，额外消耗该阶段基础工作量的 20%，暂时增加 1.5 点质量。
- 合同标准周期为死线。委员会项目在原周期结束时仍未完成全部阶段，可自动使用一次原周期 20%的延期；承制项目不延期。延期期间继续支付固定运营费和工资，压力按延期周数增长并在结算时影响声望。
- 截止时未完成全部阶段，但累计完成工作量达到总工作量 50%，按低完成度交付处理；低于该线则违约。50%只是实验阈值。

## 重要限制

1. 核心员工数量固定为 4 人；尚未接入临时员工招聘、员工能力差异、岗位分配、疲劳和成长。
2. 70 单位/周的内部产能、外包比例和单价、20%加班上限均为实验参数，不是行业报价或最终规则。
3. 非 BD 渠道开放数暂定为 2，渠道适配度仅抽取普通区间；未模拟委员会成员具体选择与高适配度项目。
4. 项目规模梯度、阶段返工、缺陷返修、质量完整计算公式、声望对市场机会反馈等尚未接入。
5. 结果适合检查现金流结构和参数方向，不足以单独证明经济系统平衡。员工模块提供真实岗位产能与临时员工规则后，必须替换当前占位值重新校准。
