# 开放式增量开发与提前实现原则

> 状态：已确认（2026-11-26）
> 适用范围：全体项目成员、贡献者与开发 Agent；适用于首版及后续版本。
> 权威边界：本文件规定协作默认行为，不替代 DECISION_LOG、DOMAIN_ARCHITECTURE、M0 契约或工程变更治理。

## 1. 核心原则

**首版范围是最低交付目标、当前优先级与工作量约束，不是对首版之外功能的禁止。**

项目采用开放式增量开发：成员可以在既定边界内自主扩展、补充体验，或提前实现原计划放在后续版本的能力。只要不违反已确认决策、不破坏主框架和跨模块契约，且没有不可接受的工程风险，新增成果默认接纳，不需要项目负责人逐项决定“要不要”。

## 2. 默认可自主推进并接纳的情况

满足以下条件时，成员可以自行设计和实现，并通过正常 PR 流程集成：

- 不与已确认玩法决策、核心体验和主框架冲突；
- 不擅自改变已冻结的跨模块接口、状态所有权和不变式；
- 不改变已确认数值基准、经济规则或既有合法行为；
- 不引入明显不可控的维护成本、安全风险或无关依赖；
- 有清晰的实现边界，并能提供与改动相称的测试和验收证据。

“默认接纳”指不再增加一道“负责人是否愿意要这个功能”的产品审批；不等于免除代码评审、测试、文档同步和正常合并流程。

## 3. 首版暂缓不构成禁止

某项能力被列为未来候选或暂不纳入首版，通常表示当前受开发时间、工作量、依赖成熟度、优先级或验收成本限制。

如果成员提前完成了该能力，且满足本原则第 2 节的条件，就没有仅因它原本属于未来版本而拒绝的理由。应按实际完成度进行工程验收；通过后可以集成，不必机械地等到后续版本。

提前实现不自动改变整体里程碑定义：阶段出口标准仍须独立满足，不能因为某个后续功能已实现就宣称整个阶段完成。

## 4. 未冻结细节的默认决策权

**没有单独冻结决策，不等于没有权限推进。** 智能体和模块负责人应先查找 DECISION_LOG、领域架构、契约、当前 main、现有测试及真实调用，再按以下顺序判断：

1. **已有规则可推导**：从现有决策和实现可以唯一或充分推导行为，直接按该依据实现，不重复提问。
2. **模块内实现选择**：不改变产品语义、玩家可见行为、经济结果、既有契约或跨模块权威的实现细节，由模块负责人自主选择；优先最小、简单、可测试的方案。
3. **低风险未决细节**：确实没有唯一答案，但影响局部、可逆且不改变玩家可见行为/经济结果时，采用最小临时假设继续推进。必须在 PR/Issue 标注 `ASSUMPTION`、理由、影响范围、回退方式和待验证点；不得将假设写成已冻结规则。
4. **实质性未决决策**：触及下节列出的边界时，才升级给项目负责人。

## 5. 必须升级给项目负责人的情况

以下事项不得以“自主扩展”或“临时假设”为由自行决定：

1. 与已确认决策冲突，或需要修改、废止既有决策；
2. 改变核心玩法、经营框架、游戏时间结构或产品定位；
3. 改变跨模块契约、状态所有权、核心不变式或失败语义；
4. 改变已确认的数值基准、经济口径或全局平衡约束；
5. 需要破坏性迁移、替换主架构，或存在重大安全、数据和维护风险；
6. 多种方案之间存在实质性的产品体验或项目控制权取舍。

遇到上述情况，先说明冲突、影响范围和可选方案，等待项目负责人裁决；不得先合入再要求追认。

## 6. 工程验收仍然有效

所有新增成果仍须遵守贡献指南和工程变更治理：

- 以最新 main 和当前权威文档为基线；
- 明确功能边界、依赖和对现有行为的影响；
- 补齐必要测试，覆盖正常、失败和关键边界；
- 同步受影响的接口、数据模型、文档和进度状态；
- 通过 PR 评审与集成验证后再进入 main；
- 如实区分提案、已设计、已实现、已验证和已集成。

功能已实现、测试已通过、已进入 main 是不同状态，不得混为一谈。

## 7. 决策口径

- **默认：** 无冲突、边界清楚、风险可控的新增能力，自主推进，验收合格后接纳。
- **例外：** 触及已确认决策、主框架、跨模块契约、核心数值或重大风险时，提交项目负责人裁决；仅暂停受影响的最小决策点，其余工作继续。
- **首版范围：** 管理最低交付和优先级，不作为拒绝提前完成且符合规则之成果的理由。

本原则由项目负责人于 2026-11-26 确认。后续协作文件与任务说明应遵循本原则；如与旧文档中“首版不做”“先审批提案”等泛化表述存在冲突，以本原则为准，但不覆盖任何具体已确认玩法决策。


## 8. 阻塞报告必须局部化

不得只写“缺少冻结决策”“等待确认”作为阻塞描述。报告必须列明：已有依据与实际缺口、受影响的最小代码/测试范围、为什么模块负责人不能自行决定、推荐方案与备选方案、等待期间仍可推进的工作。若有低风险可逆方案，默认采用并记录假设；若无安全方案，只暂停直接依赖该决定的部分，不暂停整个模块或其他并行任务。
