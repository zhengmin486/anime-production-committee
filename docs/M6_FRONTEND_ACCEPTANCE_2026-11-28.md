### Event → Vendor 契约

- `V4EventOption.vendor_request` 为 `null | { item_id, supplier_id, work_total }`。
- `work_id` 来自 pending event 所属项目；Event 外包固定 `emergency`。
- 公共 `sign_outsourcing` 回执字段在顶层；`resolve_event` 的 Vendor 回执嵌套在 `vendor`。
- 严格校验拒绝不存在的 item/supplier 引用；合法空 `risk_hint` 不再被误拒。
- 旧存档缺少 `vendor_request` 时按缺失/null 处理。
- 已用真实 WASM 集成测试验证 Event 意图展示和外包回执；本轮浏览器未抽中 Vendor 应急事件。

### 明确未伪装为可用的功能

- 外包与加班计划：前端可保存字段，但核心生产逻辑尚未消费，不显示虚假收益或费用。
- 原创草稿：核心要求声望 120，且当前草稿没有委员会候选，承接路径不可用。
- 存档：四场景原型刷新后重新开始；完整 V4 Workbench 另有存档能力。
- 正常完工：本轮四场景路线完成的是截止周强制交付并写入 Archive，不宣称全部门槛正常达标。
- 业务状态没有 Mock 成功替身；测试中的服务桥接仍调用真实本地 WASM。

## 本轮浏览器验收

环境：Windows 10、Node 22.23.5、生产预览 `http://127.0.0.1:4175/?view=prototype`、真实 v4 WASM、种子 `20261127`。浏览器视口约 `951 × 578`，长侧栏需要滚动。

### 路线 A：招聘、签约、解雇、外包与事件

1. 核心初始化：第 0 周、现金 `¥2,000,000`、声望 100、0 部在制；四场景导航和素材正常。
2. 办公室初始候选池 6 人。执行 `scout` 后现金 `¥2,000,000 → ¥1,950,000`，候选 6→7，Finance 出现 `scout -¥50,000`，本周招募按钮禁用。
3. 签约 `演出_0_0`：现金 `¥1,950,000 → ¥1,801,000`，核心员工 3→4，Finance 出现 `signing_fee -¥149,000`。
4. 二次确认后执行 `dismiss_staff`：新员工移出名册，周次保持 0，现金不因解雇变化。
5. 市场锁定“星海邮差”：支付定金 `¥60,000`；随后执行承制 `start_work`，合同拨款 `¥1,200,000`，现金 `¥1,741,000 → ¥2,941,000`，在制 0→1。
6. 林监督自动归属项目；陈原画、许动画通过 `assign_staff` 分配到 `work_01`。
7. 制作现场默认“系列构成”没有匹配供应商，签约按钮正确禁用；切换“角色设定”后选择“曙光作画协力”。
8. 执行正常模式 `sign_outsourcing`，签约 1 工作点：现金 `¥2,941,000 → ¥2,937,000`，回执为 `contract_0_01`、预付 `¥4,000`、周产能 1；作品详情出现真实合同行。
9. 执行 `set_work_plan`，验证 high/low 投入强度与 schedule 工作重点。
10. 逐周推进并处理真实事件：电视台探班、作画监督病倒、原画师体力透支、作画进度落后、外包催款；每次 pending 1→0。
11. 未查看事件时“推进本周”禁用；点击“查看事件（核心）”后才可推进，查看本身不扣款或移除事件。
