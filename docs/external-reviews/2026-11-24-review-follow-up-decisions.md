# 独立游戏设计评审后续待定事项

> 本文记录对《独立游戏设计评审报告》的逐条讨论结果，以及讨论中产生、尚未进入正式决策的补充想法。本文不是正式决策登记册，不自动修改现有规则、契约或里程碑。

## 1. 制作与市场的中途反馈（报告 P0-1：边播边做）

**讨论结论：认可长期方向，首版不实施。**

- 长期方向：播出反馈应成为真实的经营因素。未来版本可以研究观众反响、口碑、配信热度等反馈如何影响后续制作策略、资源投入、商业机会和作品经营。
- 首版范围：不引入逐集播出、边播边做、逐集市场反馈或分期收益结算；继续维持现有整部作品制作与交付结构。
- 后续研究重点：
  1. 播出反馈是否能改变玩家决策，而非只增加数值。
  2. 播出与制作如何衔接，是否允许播出期间继续制作。
  3. 反馈如何影响后续制作、商业合作和公司经营。
  4. 如何避免增加逐集排期和每周微操。
- 当前处理：不修改现有制作 DAG、整部交付规则及 M1–M7 里程碑。

## 2. 员工主要职业方向（讨论补充，待定）

朕明提出以下八个方向，作为员工主要职业方向的初步构想：

1. 作画
2. 演出
3. 脚本
4. 摄影
5. 监督
6. 音乐
7. 声优
8. 美术

**当前状态：八个基础职业已确认保留，具体职业与岗位映射见第 4 节。**

后续细化时需要区分：
- **职业方向**：员工主要从事的工作领域。
- **专业能力**：员工在该方向上的具体能力与专长。
- **制作岗位**：员工在某部作品、某个制作阶段实际承担的职责。

补充边界：
- 作画与美术分别保留，不因都涉及画面而合并。
- 演出与监督分别保留，前者偏向单集视听呈现，后者偏向整体创作把控与质量判断。
- 音乐、声优方向需允许内部员工与外部合作人员两种实现方式。
- 八个职业方向不与现有六个单集制作阶段强行一一对应；一个阶段可以由多个职业共同参与，一个职业也可能参与多个阶段。

后续仍需验证职业方向是否覆盖实际制作流程、是否需要补充或调整，以及职业方向与员工能力数值、工作项需求之间的映射方式。

## 3. 周决策密度与时间推进（报告 P0-2：半月回合或智能快进）

**初步讨论方向：优先研究增加每周可采取的有效行动，不先压缩时间步。**

用户补充意见：
- 可以考虑加速键，但这是后期公司规模扩大后的便利功能，不是解决前期节奏问题的首要手段。
- 前期以短篇 OVA 为主时，项目规模较小、经营操作相对频繁，玩家每周应该有更多可做的事情。
- 周决策稀疏问题更应该先从增加每周可采取的行动入手，而不是直接把 520 周改成 260 个半月回合。

当前分析：
- 报告指出大量周推进缺少有效决策，这一体验风险值得验证；但“改成半月制”只是解决方案之一，不应直接接受。
- 保留周作为基础时间单位，暂不改变工资、工期、疲劳、随机结算等时间口径。
- 重点研究每周行动空间：玩家每周可以做哪些经营、制作、人事、商务或项目管理操作；这些行动如何形成取舍，避免只是增加重复点击或无意义待办。
- 加速键或推进至下一关键节点可作为后期便利功能研究，随着公司和项目规模扩大再评估其必要性。
- 不预设每周必须塞满操作；目标是让玩家在需要介入时有值得做的事，而不是强迫每周完成固定数量的任务。

**当前状态：方向性意见已记录，尚未形成正式裁决。** 后续需要进一步梳理可增加的每周行动类型、行动次数/成本/机会成本，以及前期小规模经营与后期规模化经营的节奏差异。

## 4. 八个基础职业、岗位适配与职业转换（DISC-11）

**讨论结论：保留原设计的八个基础职业；职业与岗位分层；取消“跨界”适配档。**

### 4.1 职业与岗位的关系

- **职业**是员工的专业身份，保留八个基础职业：脚本、演出、作画、美术、摄影、音乐、声优、监督。
- **岗位**是员工在具体作品和工作项中承担的实际职责。
- 职业不等于岗位。员工可以承担非本职业主责的岗位，但专业适配程度不同。
- 不设置“跨界”第三档：职业与岗位专业匹配时为主责；不匹配但规则允许参与时为协力。
- 协力不是无条件胜任任何岗位。具体工作项是否允许某职业协力，仍由职业—岗位适配规则定义。

### 4.2 八职业与工作项映射

| 基础职业 | 主责工作项 | 协力工作项 | 说明 |
|---|---|---|---|
| 脚本 | `series_composition`、`script` | `episode_direction_plan` | 故事构成与脚本 |
| 演出 | `episode_direction_plan`、`storyboard` | `editing`、`animation_check` | 单集视听呈现与执行 |
| 作画 | `character_design`、`layout`、`key_animation`、`inbetween`、`animation_check` | `background` | 包含原画、中割与作画检查 |
| 美术 | `art_setting`、`background`、`color_design`、`art_check` | `layout` | 背景、美术设定与色彩 |
| 摄影 | `composite`、`editing`、`delivery_master` | `inbetween`、`sound_mix` | 视觉后期与成片输出 |
| 音乐 | `music`、`op_ed` | `sound_mix` | 独立音乐创作；允许外包音乐公司 |
| 声优 | `dubbing` | `op_ed` | 声音表演；允许项目制临时参演或外包事务所 |
| 监督 | 全片统筹把关；高阶协力 `storyboard`、`editing`、`dubbing` 配音指导 | 全流程卡壳救火与节奏把控 | 不与演出争夺普通制作岗位，特殊机制见下文 |

上述映射为当前确认的设计口径；工作项的具体配置、协力许可和数值仍需落入蓝图/员工规则并经过验证。

### 4.3 主责与协力适配

- 主责：职业与岗位专业匹配，工作效率按 100% 基准计算，正常发挥该岗位对应的专业质量贡献。
- 协力：职业与岗位不完全匹配但规则允许参与，工作效率暂按 60% 基准计算，主要用于推进进度；不因此获得该岗位的专业质量上限。
- 不设置 20% 跨界档，也不以“跨界”作为员工调度类别。
- 工作量效率、质量贡献、疲劳代价三轴独立计算。疲劳不由适配档位自动推导，具体倍率待数值标定。
- 协力人员的质量贡献不等同于效率百分比；不得简单将 60% 工作效率换算成 60% 质量。
- 适配规则必须明确哪些职业可以协力哪些岗位，不能默认所有职业都能参与所有工作项。

### 4.4 监督的三类独立特殊机制

监督不作为普通工作项产能职业处理，其价值通过独立机制体现：

1. **质量收敛（只托底，不压顶）**：仅压缩负向质量波动，不削弱正向波动。示例区间 `[-15%, +15%] → [-5%, +15%]` 仅作为标定示例，最终参数待模拟验证。
2. **质量上限影响（单向正向）**：依据监督的 `direction`、`planning` 能力及关键标签，在定调和高潮把关时提供正向评价上限加成；普通合格监督可为 +0%，高阶名监督示例为 +3%～+12%。具体计算与参数待标定，不设置低能力监督的负倍率惩罚。
3. **组织协调（衔接 DISC-13）**：
   - 普通人员接手已开始的工作项时，监督可依据 `management` 能力部分减免一次性磨合损失；减免比例待标定，示例为 20%～40%，且至少保留原损失的 60%，不得清零。
   - 监督本人切换项目时，完整触发 DISC-13 规定的团队层面一次性损失，不予减免。

三类机制分别结算，不相互替代；具体实现和数值进入后续标定。

### 4.5 六项通用 ability 与八职业分层

不为八个基础职业扩充底层 `ability`。职业映射与蓝图工作项的通用能力需求是两层配置。

当前确认的蓝图能力归属修正：
- `animation_check`：`direction` 改为 `drawing`。
- `editing`：`direction` 改为 `postproduction`。
- `storyboard`：保留 `direction`。
- `dubbing`、`music`、`op_ed`：保留 `postproduction`。

职业决定员工的专业身份及岗位适配；`ability` 描述工作项所需的通用能力。两者共同参与生产计算，但不可混为同一字段。

### 4.6 职业转换

**讨论结论：保留职业转换方向，但首版不实现复杂转职系统。**

- 员工初始职业在入职时确定。
- 员工通过实际参与相关工作积累经验与履历，具备长期转向其他职业的可能。
- 职业转换由玩家主动决定，不自动发生；原职业积累不清零。
- 职业转换不是普通岗位调动：岗位调动只改变当前承担的工作，职业转换则改变员工长期专业身份及后续主责适配关系。
- 监督转换应比普通职业转换更强调全片统筹、关键节点把关等实际履历，不能只凭能力数值达标。
- 首版先保留规则扩展空间，优先跑通八职业、岗位适配与员工成长；转换条件、成本、限制次数和具体实现留待后续验证。

## 5. 员工特性与关键主创相性（DISC-12）

**讨论结论：整体设计方向认可，作为后续员工机制设计基线；具体数值、触发概率与组合表留待模拟标定。**

### 5.1 员工特性总则

- 员工特性是员工个体机制，与基础能力、潜力、职业身份及当前岗位适配分层；特性不能替代基础能力或职业专业性。
- 每名长期员工终身最多拥有 **2 个特性**。
- 不设置特性技能树、主动洗点或玩家主动选择领悟特性的机制。
- 特性不因玩家操作而随意更换；玩家通过招聘、项目安排和长期培养影响员工的发展方向，特性由员工生成规则与实际经历决定。
- 不为老员工突然添加负面惩罚特性；后天领悟只产生正向或成长型特性。

### 5.2 特性来源：入职自带 + 实战领悟

采用“**主要来自入职生成，少量来自长期实战领悟**”的双来源结构。提案中的“80% 入职自带 + 20% 实战领悟”用于表达来源侧重，不直接作为每次招聘或每次交付的固定概率。

**入职自带：**
- 员工在招聘、scout 或临时员工池生成时，可自带 0–1 个原生特性。
- 少数高潜力或高阶 scout 候选人可以自带 2 个特性，但仍受每人终身最多 2 个的硬上限约束。
- 特性应成为招聘与挑选临时员工时的差异化信息，不应只比较六维能力数值。
- 潜力不等于特性数量；不能让高潜力档次必然获得更多特性，避免能力、潜力和特性优势过度集中。

**实战领悟：**
- 仅特性数量未满 2 个的长期员工有机会在作品交付结算、Archive 归档时，根据实际履历低频领悟 1 个后天特性。
- 领悟必须有对应经历和表现作为依据，不能仅凭参加过一部作品触发。
- 示例：主力参与同一大类题材并取得高评价，可形成题材专精；多次在高压死线下成功交付，可形成死线抗压；长期与新人协作并产生培养效果，可形成带新加速或团队润滑。
- 领悟结果自动写入周报/履历，不要求玩家主动选择特性。
- 临时员工不参与长期成长，不通过实战里程碑永久获得后天特性。

### 5.3 八种员工特性原型

| 特性 | 机制边界 |
|---|---|
| 高效率推进型 | 提高周工作量产出，但锁定质量贡献上限；不同时提升进度与质量 |
| 死线抗压型 | 仅在明确的交付倒计时窗口生效，减缓疲劳累计但不免除疲劳；周薪暂定 +10% |
| 慢工打磨型 | 质量尚未达到高阶目标前，质量相关产出更稳定或打磨效率更优；不自动延长工期，是否继续投入由玩家决定 |
| 高爆发高消耗型 | 提高质量贡献上限；工期消耗与疲劳代价独立结算 |
| 低波动保底型 | 仅收窄员工个人单次产出的随机波动，不直接提高作品质量下限 |
| 特定题材专精型 | 仅在匹配的少数大类题材下提供加成，不无限细分题材 |
| 带新加速型 | 加速同项目符合条件的新人经验获取，不直接增加新人工作产出 |
| 团队润滑型 | 降低所在项目普通人员交接磨合损失与团队疲劳；与监督的磨合减免机制合计设置上限，示例为最高减免 50%，至少保留一半原磨合损失 |

补充分层：
- 低波动保底型作用于员工个人单次工作结果的随机波动。
- 监督的质量收敛作用于项目制作过程中的负向质量波动，两者处于不同层级。
- 团队润滑型作用于所在项目普通人员的交接磨合与团队疲劳。
- 监督依据 management 能力减免普通人员交接损失；两者同时存在时合计减免不得超过约定上限。
- 监督本人切换项目产生的 DISC-13 团队层面损失仍完整承担，不受团队润滑或监督自身协调减免影响。
- 上述百分比和触发窗口均为待标定参数，不视为已经冻结的运行时数值。

### 5.4 关键主创相性

仅检查三个关键位置的组合：
- 监督位
- 脚本主责位
- 作画主责位

规则：
- 在项目立项配班时一次性计算并锁定，不随周重新计算。
- 项目中途不得通过频繁换人重新刷取相性。
- 每个项目只确定一种主要相性结果，收益不叠加。
- 多种条件同时满足时，按以下优先级判定：**节奏冲突 > 高风险高上限 > 协同稳定**。
- 相性由三个关键位置的实际特性组合决定，不能仅因其中一人拥有某特性就直接触发；具体组合判定表后续明确。
- 节奏冲突事件每部作品最多触发一次，提供一次明确的经营取舍，不持续制造重复随机麻烦。

三种相性结果：
1. **协同稳定**：偏稳健、润滑的组合，降低项目内磨合损失，并降低中期负面制作风波事件概率。
2. **高风险高上限**：偏高爆发、打磨倾向的组合，提高全片质量上限，同时增加工期压力与中期进度危机风险。
3. **节奏冲突**：例如高效率推进倾向与慢工打磨倾向形成冲突；触发一次二选一经营事件，由玩家决定优先保工期还是坚持质量。

### 5.5 防止固定最优班底

不依赖未定义的全特性周薪溢价，主要通过以下结构形成机会成本：
- 承制与委员会路线对效率、质量上限和风险承受能力的需求不同。
- 疲劳积累与红灯强制休养要求玩家进行人员轮换。
- 不同作品对八种职业及具体能力的需求存在差异。
- 多项目并发时，员工归属与人力竞争使强力员工无法同时服务所有项目。
- 特性组合带来不同优势与代价，不建立复杂、僵硬的相互克制关系。

### 5.6 后续标定事项

以下不阻碍当前机制骨架成立，留待模拟和数值标定：
1. 实战领悟的具体履历门槛与十年内合理触发频率。
2. 八种特性的具体倍率、触发窗口及组合强度。
3. 三类关键主创相性的具体组合判定表、收益与风险概率。
4. 团队润滑与监督磨合减免的合计计算方式及上限实现。

## 6. 跨议题联动与契约对齐（第五部分）

**讨论结论：整体通过，作为现有决策的交叉核对与边界整理；不新增独立决策编号，不自动修改正式决策登记册、蓝图或运行时代码。**

本节按现行契约对齐多项目并发、统一资金预检、资金危机、事件并发、系列续作与 520 周中后期节奏。凡已由正式决策确认的内容，以正式决策为准；本节不覆盖或重开既有决策。

### 6.1 多项目并发、统一预检与资金危机

**人员与外包归属：**
- 核心员工遵循“一人一周一归属”，同一周不跨项目兼职支援。
- 临时员工绑定具体项目，允许项目中途加入；项目交付或中止后自动退出并解绑。
- 临时员工不提供常规提前解约权；仅在特定事件卡明确提供选项时，才可按该事件规定的代价解约。
- 外包合同签约即占用供应商 `weekly_cap`。产能占用应依据有效合同及其剩余有效承诺计算；合同交付、终止或失败后，按合同状态和剩余承诺释放相应占用，不另建可与合同状态脱节的独立预留账本。

**财务记账与原子提交：**
- 公司维持单一现金池。
- 固定维持费、员工工资、外包费用、加班费用等分别独立记账；财务流水可以按固定顺序展示。
- 流水展示顺序不构成逐笔扣款优先级，不允许部分支付、部分拖欠，也不允许部分项目推进。
- 周结算执行统一资金预检；通过后，所有项目及相关财务变化在同一事务内原子提交。

**资金危机边界：**
- 统一预检失败后进入限时资金危机。
- 危机期间周数照常推进，继续计提固定成本；不进行制作、不计制作费用；允许现金暂时为负，不自动借款。
- 危机期限届满仍未恢复偿付能力时，进入破产结算。
- 危机期间禁止：新立项、新外包、新招聘、新建设施、购买电视服务，以及常规提前解约临时员工。
- 危机期间允许：融资、解雇核心员工、中止项目（`abort_work`）、调整未来员工归属与计划、交付已达到交付门槛的作品、推进周数。
- 调整员工归属与计划不得突破“一人一周一归属”，不得追溯改写已经结算的人员安排。
- 危机期间特殊事件的触发、可处理时机及其是否提供额外命令，仍须结合 M0 白名单进一步核对；不得仅凭一般事件机制推定危机期间可以执行白名单之外的操作。

### 6.2 多项目事件并发与结算节奏

**严格遵循 DEC-EVENT-001 与 M0 事件契约：**
- 每个项目每周至多触发一个事件；多个项目可以在同一周各自触发事件。
- 已触发事件全部保留在 `events.pending[]` 中，不覆盖、不丢弃、不合并。
- 只要 `events.pending[]` 非空，即暂停周推进；玩家可自行决定先处理哪个项目的事件，全部处理完毕后才可进入下一周。
- 不设置全局单事件槽，不设置跨项目事件优先级仲裁，也不因全局每周事件数量上限而丢弃已触发事件。

**经营信息与随机揭晓：**
- 未来企划预告、员工疲劳预警、项目死线进度、供应商剩余产能等已知信息，应作为前置明牌信号呈现。
- 有效产能的随机波动、市场刷新、部分外包交付质量波动及事件抽取结果，在对应周结算时揭晓。
- 明牌只展示当前已知状态和可推导风险，不提前泄露尚未结算的随机结果。
- 事件的具体触发条件仍由事件类型和对应规则决定；随机系统负责结果的可复现性，不要求所有事件使用同一种抽取算法。

### 6.3 续作复利与系列商业基础

**已确认：**
- 保留系列关联字段，前作商业基础可以向后续系列作品继承。
- 首版不纳入独立衍生企划、商品化任务和授权开发。
- 具体继承系数及计算方式留待数值标定。

**权利边界：**
- 投资比例不等于 IP 所有权。不得仅凭委员会投资比例达到或超过 50%，就自动认定作品 IP 归公司所有。
- 版权归属、续作开发权、窗口经营权、投资收益分配权应分别判断，不因其中一项自动推导其他权利。
- 系列商业基础继承不以公司拥有 IP 所有权为必要条件；但实际续作立项、开发权限和收益分配，必须符合对应合作关系与版权约定。

**留待后续研究，不视为已确认规则：**
1. 系列商业基础的具体继承系数。
2. 续作质量低于前作时，是否以及如何缩减商业加成。
3. 连续第三部、第四部续作是否出现继承热度的边际递减。

### 6.4 声望与 520 周中后期节奏

**声望规则边界：**
- 声望不自然衰减。
- 按时交付且达到最低质量要求的作品，仍应获得基础声望增长。
- 不采用“不接大项目就自然掉声望”或“小项目声望收益直接归零”的规则。
- 后续可在数值标定层面研究项目规模、难度和质量如何拉开声望增量差距，但不得破坏既有基础增长规则。

**中后期战略承诺：**
- 首版暂不新增“十年 3–4 次不可逆战略承诺”独立系统。
- 先依靠现有的 `buy_tv_service`、特殊商业机会的不可退还前置费用与履约义务，以及委员会项目的大额本金风险，验证长期经营循环。
- 完成首轮完整 520 周测试后，再根据中后期实际暴露的问题决定是否需要新增后期玩法；不预先规定战略承诺次数或强制出现时间。

### 6.5 归档结论与实施边界
