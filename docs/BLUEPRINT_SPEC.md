# 制作蓝图规范（Blueprint Spec）

> 状态：v0.5 内容契约与运行时样例；配套样例 [`blueprints/tv_standard.blueprint.json`](blueprints/tv_standard.blueprint.json)
> 上位文档：[领域架构设计](DOMAIN_ARCHITECTURE.md) §7.3；权威玩法：[DECISION_LOG](DECISION_LOG.md) DEC-PROD-001/002/003/006
> 校验命令：`npm run validate:blueprint`
>
> 公共制作 + 单集 + 跨容器依赖 + 交付门槛是制作结构的核心。蓝图必须能被实例化、依赖无环、门槛可达、粒度可读；字段清单本身不能替代这些可检查证据。

---

## 1. 蓝图是什么，不是什么

| 是 | 不是 |
| --- | --- |
| 一部作品的工作项模板：公共制作项 + 单集项 + 依赖 + 门槛 | 一部具体作品的状态（状态在 Project 里，立项时实例化） |
| 内容配置，可按规模/题材制作多份 | 平衡表（结构校验不证明经济与工期平衡） |
| 立项时展开为 N 个单集的依据 | 运行时可变对象（实例化后冻结，改蓝图不影响在制项目） |

一份蓝图只描述**一部作品**。公司可以同时持有多个项目，每个项目用自己的蓝图实例。

---

## 2. 结构

```json
{
  "schema_version": 1,
  "id": "tv_standard",
  "name": "常规 TV 季番（10 集）",
  "scale": "tv",
  "episode_count": 10,
  "work_unit": "centi_staff_week",
  "common": [],
  "episode": []
}
```

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| `schema_version` | 必须为 `1` | 结构变更时升版，不与存档版本混用 |
| `id` | 小写 snake_case，全局唯一 | 企划通过 `blueprint_id` 引用 |
| `scale` | `ova` / `short` / `tv` / `movie` | 与企划规模一致；不一致直接拒绝 |
| `episode_count` | 正整数；`tv_standard` 必须为 10 | 其他模板的常见集数范围只给警告，最终以对应企划矩阵为准 |
| `work_unit` | 固定 `centi_staff_week` | 冻结枚举名；当前 v0.5 runtime 按 **1 人周 = 70 工作点** 换算，不按枚举名字面作 1/100 换算 |
| `common[]` | 非空 | 项目级公共制作，无阶段，全部不可外包 |
| `episode[]` | 非空，六阶段全覆盖 | 单集模板，实例化时复制 N 份 |

### 2.1 工作项字段

| 字段 | 适用 | 约束 |
| --- | --- | --- |
| `key` | 全部 | 小写 snake_case，同容器内唯一；实例化后变成 `ep01.script` 这类 id |
| `name` | 全部 | 展示文案 |
| `stage` | 仅单集项 | 必须是六阶段键之一 |
| `ability` | 全部 | 驱动该工作项的专业能力（六项之一） |
| `work_total` | 全部 | 正整数，单位见 `work_unit` |
| `deliver_at` | 全部 | 1–1000，最低交付门槛占 `work_total` 的千分比 |
| `deps` | 全部 | 依赖 key 数组；跨容器写 `common:<key>` |
| `is_gate` | 仅单集项 | 是否为作品交付门槛项；至少一个，且建议 `deliver_at=1000` |
| `outsourceable` | 全部，必填布尔 | 公共制作与 gate 必须为 false；只有 episode 非 gate 项可外包 |
| `quality_weight_permille` | 全部，必填整数 | 全片质量权重，0–1000‰；`Σcommon + Σepisode = 1000‰`，且每个单集的权重和必须相同（DEC-STAFF-008） |
| `core_aesthetic` | 全部，必填布尔 | 是否为核心审美工序；只有 true 且 `S_sup>70、Q_item>70` 才获得核心审美奖励（DEC-STAFF-008） |

`WorkItem.outsourceable` 在实例化时写入 Project，并随存档序列化；不能用阶段名或 gate 状态在运行时临时替代该字段。

`WorkItem.quality_weight_permille` 决定这个工作项在"作品分"里占多大权重：公共层与单集层各自归一后再按层权重合成（v0.5 为公共 200‰ / 单集 800‰），所以单集数量变化不需要重写权重。实例化写入 Project 并随存档序列化，运行时不按阶段名硬编码权重。

### 2.2 阶段键（顺序固定）

```text
content_design → storyboard_key_animation → animation
→ art_visual → photography_editing → sound_delivery
```

阶段顺序只用于**分派排序的兜底优先级**与 UI 分组，**不是门禁**。真正的先后关系全部由 `deps` 表达。

## 3. 依赖与门槛的语义

```text
delivered(item)  ⇔  work_done × 1000 >= deliver_at × work_total
unlocked(item)   ⇔  ∀ dep ∈ deps: delivered(dep)
```

- **门槛解锁，完成不解锁**：A 达到 `deliver_at` 就解锁 B；A 仍可继续做到 100% 只提质量。
- **跨容器**：公共项是单集项的上游（`common:character_design` → `layout`），不需要额外的“公共阶段”。
- **跨单集不允许**：TV 的多集并行靠“每集独立成链”实现，不把第 2 集挂到第 1 集后面。
- **门槛项**：作品可交付 = 全部 `is_gate` 项 `delivered`。强制交付时用 `gate_completion_permille` 计算扣罚与评价修正。
- **外包边界**：只有 `outsourceable=true` 的 episode 非 gate 项可接受外包合同；公共制作与最终母版把关留在社内。

## 4. 校验器检查什么

`npm run validate:blueprint` 默认校验 `docs/blueprints/tv_standard.blueprint.json`。

| 类别 | 检查 | 级别 |
| --- | --- | --- |
| 结构 | 必填字段、类型、取值范围、key 格式与唯一性 | 错误 |
| 单位 | `work_unit` 必须声明 | 错误 |
| 外包 | `outsourceable` 必填且为布尔；公共项与 gate 不可外包 | 错误 |
| v0.5 TV-小 | 10 集、公共 4,800、单集 2,100、核心 580、可外包 1,520 | 错误 |
| 阶段 | 六阶段必须全部有工作项 | 错误 |
| 门槛 | 至少一个 `is_gate`；门槛项 `deliver_at≠1000` 给警告 | 错误 / 警告 |
| 依赖 | key 可解析、不自指、不重复、公共项不得依赖单集项 | 错误 |
| 图 | 公共图与单集图分别检测环 | 错误 |
| 可达性 | 每个工作项都在某条通往门槛项的链上；公共项必须被引用 | 警告 |
| 量级 | 单集工作量在 1–30 人周之外、公共制作占比 > 30% | 警告 |

校验器**不判定平衡**。它只回答“这份蓝图能不能被安全实例化和推进”，以及当前 `tv_standard` 是否符合 v0.5 硬锚点。

## 5. 当前样例读数（`tv_standard`，10 集）

```text
单集工作项      12 个   2,100 点（30.00 人周）
  不可外包       7 个     580 点
  可外包         5 个   1,520 点
公共制作项       5 个   4,800 点（68.57 人周），全部不可外包
实例化后       125 个  25,800 点（368.57 人周）
公共制作占比            18.6%
单集关键路径          1,780 点（25.43 人周）
```

阶段分布：内容设计 2 项 / 分镜与原画 2 项 / 动画 1 项 / 美术与视觉 2 项 / 摄影与剪辑 2 项 / 声音交付 3 项。

公共制作包含系列构成 1,500、角色设计 1,000、美术设定 500、片头片尾 900、音乐 900 点。单集核心 580 点覆盖脚本、演出、分镜、摄影合成、混音与最终母版把关；可外包 1,520 点覆盖原画、动画、背景、上色、剪辑与声音控制。

## 6. 必须用这套结构证明什么

| 待证明 | 怎么证 |
| --- | --- |
| 蓝图能实例化为合法项目 | 用样例跑 `start_work`，校验器 + 状态校验双通过 |
| 依赖与门槛语义正确 | 手算：把某集推到 `deliver_at`，确认误报/漏报为零；下游解锁、上游仍可继续 |
| 跨容器依赖成立 | 公共项未达标时，依赖它的单集项不可开工 |
| 门槛与交付一致 | 门槛全集达标后 `deliver_work` 通过；缺一项则拒绝 |
| 外包边界成立 | 公共项与 gate 即使被标记可外包也拒绝；合法 episode 项按合同推进 |
| 粒度可读 | 用 12 项/集跑一集，检查周回执是否还能读懂 |
| 数量可控 | 10 集实例化后的状态体积与单次推进耗时 |

**当前样例的定位**：v0.5 十集验收蓝图。结构、集数和核心/可外包拆分已经冻结为当前锚点；经济、产能与最终平衡仍由对应模拟和人工试玩验证。

---

## 7. 待定与边界

- 不同规模是否共用同一份阶段模板：当前 `movie`/`ova` 复用 episode 模板、`episode_count=1`，暂不为剧场版单独设计公共制作结构。
- 是否需要“未开工单集”的懒实例化：当前全量实例化，`tv_standard` 为 125 项。
- 非 TV 蓝图的具体阶段工作量拆分尚未冻结，不得从 TV 模板自行推算后宣称已确认。
- 工作项命名与数量是内容工作，需与企划样本对齐。
- 蓝图不承载美术/文案资源，只承载生产结构。
