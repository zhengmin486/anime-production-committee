## 1. 我们要做一款什么游戏

《动画制作委员会》是一款以开罗游戏为主要设计参考的轻量动画制作公司经营模拟游戏，浏览器端、单人。

玩家经营一家动画制作公司，在十年的经营周期内，通过承接动画企划、组织作品制作、参与制作委员会、建立产业合作关系，逐渐成长为一家拥有优秀人才、代表作品和行业影响力的动画公司。

本作不是现实动画产业链的完整沙盘，不是逐镜头制作模拟，也不是单纯的委员会投资模拟器。我们希望玩家通过有限但有分量的经营决策，组织人才与产业资源，推动作品完成，在机会、风险和意外中建立自己的动画事业。

**产业设定：当代（配信主导的产业环境）。** 这不是 2005 年円盤时代的日本动画业。映像软件（BD/DVD）是最小的窗口，配信与商品化才是主战场；制作委员会的核心现金流来自立项期的配信预付与后端授权，而不是等作品卖不卖得动。这个设定决定了整套收入结构、风险形状和委员会玩法，不是可以后调的皮肤。

### 1.1 趣味假设（可证伪）

> **这款游戏好玩的核心是：玩家愿意为"下一部押什么"反复权衡，而不是为"这一周怎么排"反复操作。**

如果出现以下任一情况，说明这个假设是错的，需要重做核心循环而不是调数值：

- 玩家在第 3 部作品之后，开始用同一套配置点推进，不再打开项目面板；
- 玩家在十年结束时，回忆不起任何一部作品的名字或任何一次押注；
- 玩家的最优策略退化为"接最多的小活"或"永远承制"，即没有一个需要用判断换收益的时刻。

`[PLACEHOLDER · 验证路径：首版可玩原型 5 人 × 8 小时试玩，记录上述三条信号]`

### 1.2 目标玩家与节奏基线

| 项 | 基线 | 状态 |
|---|---|---|
| 平台 | 浏览器，单人，键鼠 | 已定（见 PRODUCT.md） |
| 目标玩家 | 玩过开罗系经营模拟、对动画产业有兴趣但不要求行业知识的人 | 假设 |
| 单局总时长 | 6–10 小时（520 周 ≈ 每周 40–70 秒） | `[PLACEHOLDER · 若实测 15 小时，每周决策密度需减半]` |
| 预期交付作品数 | 10–18 部 / 520 周 | `[PLACEHOLDER · 对照实验给出 11.8–13.3 部]` |

**为什么要把这三个数写死在愿景里：** 它们决定每周该有几个决策。如果单局只有 6 小时，一周就是 40 秒，那玩家不可能每周做三次判断；如果交付 40 部作品，玩家记不住任何一部，"代表作"这个概念就不存在。这两个数不是美术参数，是设计地基。

## 2. 公司、作品与制作委员会

### 2.1 公司：玩家长期经营的主体

玩家经营的是动画制作公司，不是委员会，也不是某一部作品。

公司是长期存在的经营主体，持续积累资金、财务记录、核心员工与人才储备、设施与长期资产、公司声望与作品履历、投资方与发行商等长期合作关系。公司可以同时经营多部作品；员工、现金和外部产能属于公司层面的共享资源，多个项目会竞争这些资源。某部作品结束，不会让公司重置。

**公司成长的意义不是让数字变大，而是让玩家吃到以前吃不到的东西。** 具体到本作，成长的第一件可感知的事是**终于吃得下一张像样的委员会席位**：50% 席位需要先垫付制作费的六成现金，起步公司拿不出，成熟公司拿得出。这条比"声望+5"具体得多，也是成长唯一能被玩家直接感知的形态。

### 2.2 作品：经营活动的核心目标与项目载体

作品是玩家最直接追求的目标，也是公司组织制作和商业活动的载体。

每部作品有独立的企划定位、规模、集数、制作计划、进度、质量、风险、商业安排和最终结果。作品制作由项目级公共制作与单集制作两层构成，单集采用六阶段流程，工作项按依赖关系和最低交付门槛推进，各集进度可以不同步。

作品不是一条等待填满的进度条。玩家应该能感受到制作瓶颈、阶段差异、质量取舍、团队表现和突发变化，并理解自己的经营决策如何影响最终成果。

### 2.3 制作委员会：围绕特定作品组织的临时合作机制

制作委员会不是玩家长期经营的公司，也不是全局共享的资源池。它是围绕**采用委员会合作模式的具体作品**建立的项目级临时合作组织，用于组织投资方与产业伙伴，为该作品提供资金、商业渠道与产业资源。

委员会由若干成员构成，成员不只是一个出资数字。成员带来的是**准入**：电视台成员对应播出档期，出版社成员对应改编可能，发行商对应海外与网络渠道。**一个成员对应一个商业渠道，加入即开放；渠道开放不由投资比例推导，投资比例也不因渠道而变。** 这是两个独立维度，玩家要同时权衡"自己出多少钱"和"拉谁进来"。

委员会的资金不是只靠后端分成。当代产业条件下，最大的单笔收入是**立项期谈定的配信预付**——平台在作品还没做完时就付一笔授权费。这笔钱决定了委员会的风险形状：它把"赌零售"变成了"卖授权"，也让高投资比例从自杀变成了有依据的押注。

**并非每部作品都必须成立制作委员会。** 普通企划可以选择承制模式，也可以选择委员会模式；原创企划必须采用委员会模式。承制与委员会是不同的商业合作方式，但作品仍由公司组织制作，使用同一套制作能力和生产流程。

委员会跟随对应作品成立。作品完结并完成项目结算后，委员会停止活动；但合作关系不会清零，曾经合作过的对象及合作结果可以沉淀为公司的长期关系资产。委员会的生命周期是项目级的，公司的经营生命周期则持续十年。

### 2.4 承制与委员会：两种商业身份

承制和委员会不是难度档位，是两种身份。

| | 承制 | 制作委员会 |
|---|---|---|
| 公司身份 | 受托制作方 | 制作方 + 投资方 |
| 收入 | 制作费与制作毛利，封顶 | 制作毛利 + 按投资比例分享各窗口收益 |
| 商业表现的杠杆 | 几乎没有，好作品只影响后续接单 | 强，好作品直接放大收益 |
| 自有 IP | 无 | 高投资比例可取得续作权 |
| 下行 | 低位但稳定 | 可能亏掉本金 |

承制的收益曲线是一条水平线，委员会的是一条斜线。**承制永远不会让公司变大，但它让公司活到能押注的那一天。** 这是本作最重要的一个经济事实，也是十年经营节奏的来源。

### 2.5 三者如何形成经营闭环

```text
公司：长期持有资金、人才、声望与合作关系
  │
  ├─ 接普通企划 ── 选择合作模式 ─┬─ 承制：只做制作方，收制作费
  │                              └─ 委员会：出资 + 拉成员 + 拿渠道
  │
  └─ 发起原创企划 ── 必须采用委员会模式
                  │
                  ▼
          作品：组织制作并形成交付成果
                  │
                  ▼
       商业结算、作品评价与合作结果
                  │
                  ▼
公司获得收益、经验、声望与长期合作积累
                  │
                  └────影响下一轮企划与经营选择
```

三者的定位必须始终清楚：**公司是玩家经营的主体，作品是玩家追求的核心目标，委员会是围绕特定作品连接投资与产业资源的机制。** 不能把游戏做成只经营委员会的投资模拟器，也不能因为强调公司经营，就让作品退化成普通项目管理任务。

## 3. 核心循环

### 3.1 三层循环

| 层 | 时间尺度 | 玩家的动作 | 必须提供的反馈 |
|---|---|---|---|
| 瞬时 | 0–30 秒 | 推进一周；处理**本周唯一一个**待处理项（产能缺口 / 关键节点 / 定向失效） | 周回执说清发生了什么、为什么、哪一项需要你决定 |
| 单局 | 5–30 分钟 | 选企划、定合作模式、配人员与方针、看一部作品从开工到交付 | 交付时能看到"我当初的那些决定"变成了这个结果 |
| 长线 | 数小时–十小时 | 积累资金与人才、提升声望、建立系列 IP、押注原创与档期 | 三年后能做到三年前做不到的事 |

**每周只能有一个待处理项。** 多项目并行已经提供了足够的信息量，再加清单就把游戏变成管理软件。没有待处理项时不显示卡片，不弹窗。

### 3.2 玩家追求的三个层次

**短期：做好眼前的作品。** 选择值得投入的企划，决定合作模式，组织团队和资源，控制成本、进度与风险，处理制作过程中的问题，最终交付一部令人满意的作品。

**中期：建立有能力的公司。** 积累资金、培养员工、改善工作环境、提升声望、拓展合作关系，并逐渐具备并行经营多部作品、吃下更大委员会席位的能力。

**长期：建立自己的动画事业。** 在十年周期中形成自己的公司特色：核心人才、代表作品、稳定的产业关系、系列 IP，以及能持续经营的商业模式。

### 3.3 押注：故事从哪来

十年经营里允许 3–4 次**战略承诺**：押注原创、押注系列、押注档期。承诺当场付钱、未来兑现、中途不可撤销。

这是本作唯一能生产"经营故事"的部件。玩家会在十年后记得的不是某周省了多少钱，而是"第三年我们押了一部原创，亏了"或者"第七年那部赌对了，才有了后面的系列"。

## 4. 核心乐趣（设计支柱）

五条支柱**有优先级**。设计冲突时，序号小的赢；如果小的赢不了，说明系统需要重做，不是需要破例。

| 优先级 | 支柱 | 冲突时的裁决 |
|---:|---|---|
| 1 | **有代价的取舍**：资源有限，每个选择都要放弃另一个 | 任何"两全"的设计都作废，哪怕它更好玩 |
| 2 | **公司成长改变可做的事**：成长必须解锁新选项，而不是放大旧数字 | 与"人手保留"冲突时，砍系统，保成长 |
| 3 | **作品有过程感**：玩家能识别瓶颈与风险，看到决策如何变成结果 | 与"操作简化"冲突时，宁可多一层信息，也不做纯进度条 |
| 4 | **人才是长期资产**：员工有专业、经验、潜力与状态，玩家会记住他们 | 与"产能算法简单"冲突时，宁可算复杂，也不把人当数字 |
| 5 | **可理解但不可完全预测的随机**：结果可解释、可复现，波动不能压过决策 | 与"刺激感"冲突时，宁可平淡，也不做不可解释的骰子 |

**明确的冲突裁决示例：** 培养一个员工需要让他上项目，控制成本需要让他下来。支柱 1 与支柱 4 冲突时，**支柱 1 赢**——成本压力优先，员工成长必须能在"被换下来"的情况下继续，否则就是设计缺陷，而不是让人破例。

随机性应当制造意外、惊喜、危机和值得复盘的故事，而不是用不可解释的骰子结果否定玩家决策。

## 5. 玩家如何参与经营

游戏以十年、520 周为周期，以周为统一时间步长。玩家主要负责四件事：**选择项目、决定合作模式与委员会构成、制定项目方针、分配公司共享资源。**

已经配置的持续方针和资源计划自动执行。玩家不应每周重复安排所有员工或重新填写所有选项。

**玩家每周的轻量杠杆是"定向"**：每部在制作品最多设一个定向目标（某单集、某阶段，或不设），只影响项目内部产能分派的排序优先级，不额外花钱，代价是被挪走的那些单集的机会成本。设置一次持续生效，直到修改或项目结束。

推进一周时，公司与所有符合条件的在制项目统一结算。项目之间会因共享员工、资金和外部产能相互影响。玩家应能从周回执看懂发生了什么、为什么发生，以及哪一项需要处理。

## 6. 风格与参考方向

开罗游戏是本项目的主体参考。我们借鉴的是它的经营模拟设计方式，不是像素美术：

- 系统容易理解，玩家能快速掌握基本规则；
- 决策数量有限，但选择会产生真实影响；
- 经营结果及时、直观且有反馈；
- 员工、设施、项目和资源之间有清晰联系；
- 成长、解锁和长期目标能持续驱动玩家；
- 随机变化让每局经历不同；
- 玩家可以快速理解局势，不需要行业知识。

其他作品可以为特定机制提供参考，但不能让整体设计失去统一性。现实动画产业是设计素材，不是必须完整复刻的对象。

## 7. 明确不做的方向

| 不希望的方向 | 原因 |
|---|---|
| 工作流或项目管理软件 | 玩家应该经营公司，而不是管理任务清单 |
| 现实动画产业 ERP | 过多商业细节会稀释核心经营乐趣 |
| 逐镜头、逐帧制作模拟 | 操作粒度过细，玩家负担过高 |
| 纯委员会投资模拟器 | 委员会服务于具体作品，不是游戏全部 |
| 单纯数值增长游戏 | 数值增长必须改变实际经营能力或未来机会 |
| 无意义的每周微操 | 重复操作不等于经营深度 |
| 纯随机游戏 | 随机不能压过玩家决策和长期经营 |
| 彼此割裂的功能集合 | 所有系统都应共同服务于公司经营与作品目标 |
| 只看终局现金的成败判定 | 十年经营的意义是"建立了什么"，不是"账户余额" |
| 円盤时代的经济模型 | 当代产业下 BD 是最小窗口，照搬会让整条价值链失真 |

## 8. 失败状态：坏掉是什么样子

愿景文档必须给失败一个形状，否则所有系统都会朝"更安全"的方向调。

| 层级 | 失败 | 后果 |
|---|---|---|
| 项目 | 延期、质量不达标、商业失败 | 扣罚、声望损失、关系恶化、后续机会减少。**不等于公司破产** |
| 季度 | 强制费用预检失败 | 进入限时资金危机：周数正常推进，固定成本继续计提，现金可为负（欠付），禁止新增承诺，玩家可融资、解雇、终止项目自救 |
| 公司 | 危机期限内未恢复偿付能力 | 破产结算，游戏失败。破产是终局，不因其他项目回款而撤销 |

**设计意图：** 破产必须是一个"看得见、来得及救、但确实会死"的过程。立刻破产太廉价，永远不会破产则十年经营没有赌注。

## 9. 设计与实现的判断标准

设计或实现任何系统时，按顺序回答：

1. 它是否增加了有意义的经营选择？
2. 它是否让玩家的决策产生真实、可理解的影响？
3. 它是否增强了作品制作过程的变化和反馈？
4. 它是否让员工、公司或产业关系产生实际价值？
5. 它是否为长期经营提供了新的动力？
6. 它带来的体验价值是否值得增加的复杂度？**（受 §10 复杂度预算约束）**

一个系统即使技术上实现完整，如果没有增加经营乐趣，也不应仅因为已经投入开发就被保留。为了方便实现而做的简化，也要判断是否会限制后续玩法。

**已经确认的玩法决策以 [DECISION_LOG.md](DECISION_LOG.md) 为准。** 认为已确认决策不合理时，应提出有证据的变更建议，说明理由、影响和替代方向，交负责人裁决，不得因局部实现方便而擅自改变。

## 11. 成品成功的判断

不以系统数量、代码规模或文档数量衡量。目标成品应当做到：

| 标准 | 怎么验证 |
|---|---|
| 玩家能理解公司、作品、委员会三者关系 | 首次游玩 30 分钟内能自己说出三者的区别 |
| 公司资源有限，需要作有意义的选择 | 试玩中出现"两个都能接但只能接一个"的场景，且玩家会犹豫 |
| 不同员工、合作模式、经营策略产生不同结果 | 固定策略模拟中，各路线期末成果差距在同一数量级但方向不同 |
| 每部作品的制作过程有变化 | 玩家能说出某部作品卡在哪、为什么 |
| 委员会确实连接具体作品的投资与产业资源 | 玩家能解释"我拉这个成员进来是为了哪个渠道" |
| 公司成长改变未来机会与制作能力 | 玩家在后期能接早期完全做不了的项目 |
| 随机性产生可理解、可复盘的经历 | 试玩后访谈能讲出一个具体事故及其原因 |
| 玩家愿意为下一部继续经营 | 十年结束时主动开始第二局的比例 |

希望玩家在十年结束时感受到：

> 这家公司是我一点点经营起来的。
>
> 这些作品是我组织团队制作出来的。
>
> 这些员工陪伴公司走过了很多年。
>
> 我经历过失败，也抓住过机会。
>
> 十年过去，我建立了一家真正属于自己的动画公司。
