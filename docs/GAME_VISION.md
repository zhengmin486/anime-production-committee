# 《动画制作委员会》游戏愿景与产品方向

> 状态：产品愿景初稿（v0.1），待团队审查
> 日期：2026-11-24
> 适用范围：产品设计、玩法设计、内容制作、程序实现、前端表现与测试
> 本文描述目标游戏与体验，不代表相关功能已经实现。
>

## 1. 我们要做一款什么游戏？

《动画制作委员会》（Anime Production Committee）是一款以开罗游戏为主要设计参考的轻量动画制作公司经营模拟游戏。

玩家经营一家动画制作公司，在十年的经营周期内，通过承接动画企划、组织作品制作、参与制作委员会、建立产业合作关系，逐渐成长为一家拥有优秀人才、代表作品和行业影响力的动画公司。

本作不是现实动画产业链的完整沙盘，不是逐镜头制作模拟，也不是单纯的委员会投资模拟器。我们希望玩家通过有限但有分量的经营决策，组织人才与产业资源，推动作品完成，在机会、风险和意外中建立自己的动画事业。

**一句话概括：玩家经营一家公司，通过制作一部又一部作品，让公司持续成长；制作委员会是公司与作品之间连接投资方及产业资源的重要机制。**

## 2. 公司、作品与制作委员会：游戏的基础关系

公司、作品和制作委员会是三个不同层次的对象。它们彼此连接，但不能混为一谈。

### 2.1 公司：玩家长期经营的主体

玩家经营的是动画制作公司，不是委员会，也不是某一部作品。

公司是长期存在的经营主体，持续积累：
- 资金、财务记录与经营能力；
- 核心员工、人才储备与团队经验；
- 设施、办公环境及长期资产；
- 公司声望、作品履历与系列经验；
- 投资方、版权相关方、发行商、电视台、供应商等长期合作关系。

公司可以同时经营多部作品。员工、现金和外部产能属于公司层面的共享资源，多个项目会竞争这些资源。某部作品结束，不会让公司重置；公司继续经营，并将项目结果转化为未来的能力、机会和风险承受空间。

公司成长的意义不是让数字单纯变大，而是逐渐获得过去做不到的事：接触更好的企划、吸引更合适的人才、承担更复杂的项目，并有能力持续制作优秀作品。

### 2.2 作品：经营活动的核心目标与项目载体

作品是玩家最直接追求的目标，也是公司组织制作和商业活动的载体。

每部作品都有独立的企划定位、制作规模、制作计划、进度、质量、风险、商业安排和最终结果。公司可以同时经营多部作品；不同作品可以处于不同制作阶段，并争夺公司有限的人才、资金和外部资源。

作品制作由项目级公共制作与单集制作两层构成。单集制作采用已确认的六阶段流程，工作项按依赖关系和最低交付门槛推进。各集进度可以不同步，前序成果达到下游工作所需门槛后可以继续完善，不要求整部作品所有工作整齐地串行推进。

作品不是一条等待填满的进度条。玩家应该能够感受到制作瓶颈、阶段差异、质量取舍、团队表现和突发变化，并理解自己的经营决策如何影响最终成果。

### 2.3 制作委员会：围绕特定作品组织的临时合作机制

制作委员会不是玩家长期经营的公司，也不是全局共享的资源池。它是围绕采用委员会合作模式的具体作品建立的项目级临时合作组织，用于组织投资方及其他产业伙伴，为该作品提供资金、商业渠道或其他合作资源，并形成相应的利益分配与风险承担关系。

委员会可能连接投资方、版权相关方、出版社、发行商、电视台及其他产业合作伙伴。不同成员提供的资源和合作条件可能不同；成员价值不只是出资，还可能来自其掌握的渠道、权利或产业资源。

**并非每部作品都必须成立制作委员会。** 普通企划可以选择承制模式，也可以选择制作委员会模式；原创企划按现行规则必须采用委员会模式。承制与委员会模式是不同的商业合作方式，但作品仍由公司组织制作，使用同一套制作能力和生产流程。委员会模式不会自动提高作品制作质量。

委员会跟随对应作品成立。作品完结并完成项目结算后，委员会停止活动；但合作关系不会因此清零。曾经合作过的对象及合作结果可以沉淀为公司的长期关系资产，影响未来项目的合作机会与条件。委员会的生命周期是项目级的，公司的经营生命周期则持续十年。

### 2.4 三者如何形成经营闭环

```text
公司：长期持有资金、人才、声望与合作关系
  │
  ├─ 承接普通企划：以承制模式组织制作
  │
  ├─ 选择委员会模式：围绕作品组织投资方与产业伙伴
  │
  └─ 发起原创企划：按规则通过委员会组织投资
                  │
                  ▼
          作品：组织制作并形成交付成果
                  │
                  ▼
       商业结算、作品评价与合作结果
                  │
                  ▼
公司获得收益、经验、声望与长期合作积累
                  │
                  └────影响下一轮企划与经营选择
```

因此，三者的定位必须始终清楚：

- **公司是玩家经营的主体。**
- **作品是玩家追求的核心目标。**
- **委员会是围绕特定作品连接投资与产业资源的机制。**

不能把游戏做成只经营委员会的投资模拟器，也不能因为强调公司经营，就让作品退化成普通项目管理任务。

## 3. 玩家追求的三个层次

### 短期：做好眼前的作品

选择值得投入的企划，决定合作模式，组织团队和资源，控制成本、进度与风险，处理制作过程中的问题，最终交付一部令人满意的作品。

### 中期：建立有能力的公司

积累资金、培养员工、改善工作环境、提升声望、拓展合作关系，并逐渐具备并行经营多部作品的能力。公司不再只能被动接受有限机会，而是能够主动选择更好的项目和经营路线。

### 长期：建立自己的动画事业

在十年的经营周期中，形成自己的公司特色：培养核心人才、制作代表作品、建立稳定的产业合作关系、积累系列 IP，并形成能够持续经营的商业模式。十年结束时，玩家应该能够回顾公司历史，看到自己建立了一家怎样的动画公司。

## 4. 核心乐趣

### 4.1 有代价的经营取舍

公司资源有限，玩家必须在资金、人才、进度、质量、期限和风险之间作出选择。例如：优秀员工应该安排给哪部作品；是否为了好企划承担投资风险；是否增加外包；是否继续打磨已达到交付门槛的作品；是否同时承担更多项目。

这些选择不应该永远存在一个明显正确的答案。不同经营路线应当产生不同收益、成本、机会和风险。

### 4.2 有变化的作品制作

作品制作需要让玩家感受到过程，而不只是看到一个总进度数字。不同集数处于不同阶段，公共制作成果逐步解锁下游工作，工作量与质量分别变化，人员和外包资源影响制作表现。玩家应能识别瓶颈、理解风险，并看到前期决策如何影响后续制作。

### 4.3 有差异的长期人才

员工不是可以随意替换的产能数字。不同员工拥有不同专业能力、经验、潜力和状态。人员安排应影响工作结果；员工参与项目、积累经验和逐渐成长，也应成为公司长期经营的一部分。玩家应该有机会记住那些陪伴公司成长、参与代表作品的员工。

### 4.4 可理解但不可完全预测的随机性

每周推进会带来工作量波动、质量变化、事件和经营机会。玩家能够通过人员能力、计划和资源影响结果，但不能在推进前准确知道所有结果。

随机性应制造意外、惊喜、危机和值得复盘的经营故事，而不是用不可解释的骰子结果否定玩家决策。结果需要可解释、可复现，随机波动不能压过玩家选择和团队能力。

### 4.5 能够影响未来的长期积累

作品结束后，员工经验、公司声望、合作关系、系列 IP 和作品履历应当对未来经营产生实际影响。今天的选择应能改变几年之后可获得的机会、可承担的项目和公司的经营能力。

## 5. 玩家如何参与经营

游戏以十年、520 周为经营周期，以周为统一时间步长。玩家主要负责选择项目、决定合作模式、制定项目方针、分配公司资源，并在重要事件、预算承诺和项目节点上作出判断。

已经配置的持续方针和资源计划应能自动执行。玩家不应每周重复安排所有员工或重新填写所有选项；需要玩家介入的，应是人员重新分配、新增外包、重大预算承诺和其他具有真实机会成本的决策。

推进一周时，公司与所有符合条件的在制项目统一结算。项目之间会因共享员工、资金和外部产能而相互影响。玩家应能从周回执中看懂发生了什么、为什么发生，以及哪些结果需要进一步处理。

## 6. 风格与参考方向

开罗游戏是本项目的主体参考。我们主要借鉴其经营模拟的设计方式，而不是只模仿像素美术：

- 系统容易理解，玩家能够快速掌握基本规则；
- 决策数量有限，但选择会产生真实影响；
- 经营结果及时、直观且有反馈；
- 员工、设施、项目和资源之间存在清晰联系；
- 成长、解锁和长期目标能够持续驱动玩家；
- 随机变化让每局经营经历有所不同；
- 玩家可以快速理解局势，不需要掌握复杂行业知识。

其他优秀游戏可以为特定机制提供参考，例如随机事件、人才成长或长期经营，但不能让整体设计失去统一性。现实动画产业是设计素材，不是必须完整复刻的对象。

## 7. 明确不做的方向

以下方向与本项目定位不符：

| 不希望的方向 | 原因 |
|---|---|
| 工作流或项目管理软件 | 玩家应该经营公司，而不是只管理任务清单 |
| 现实动画产业 ERP | 过多商业细节会稀释核心经营乐趣 |
| 逐镜头、逐帧制作模拟 | 操作粒度过细，玩家负担过高 |
| 纯委员会投资模拟器 | 委员会服务于具体作品，不是游戏全部 |
| 单纯数值增长游戏 | 数值增长必须改变实际经营能力或未来机会 |
| 无意义的每周微操 | 重复操作不等于经营深度 |
| 纯随机游戏 | 随机不能压过玩家决策和长期经营 |
| 彼此割裂的功能集合 | 所有系统都应共同服务于公司经营与作品目标 |

## 8. 设计与实现的判断标准

设计或实现任何系统时，都应该从产品目标出发判断：

1. 它是否增加了有意义的经营选择？
2. 它是否让玩家的决策产生真实、可理解的影响？
3. 它是否增强了作品制作过程的变化和反馈？
4. 它是否让员工、公司或产业关系产生实际价值？
5. 它是否为长期经营提供了新的动力？
6. 它带来的体验价值是否值得增加的复杂度？

一个系统即使技术上实现完整，如果没有增加经营乐趣，也不应仅因为已经投入开发就被保留。反过来，为了方便实现而进行的简化，也要判断是否会限制后续玩法，或把产品逐渐引向错误方向。

### 对开发成员与智能体的要求

本文件定义产品目标和判断原则，不规定具体算法、数据结构或技术实现方式。成员和智能体应理解产品愿景后，结合现有玩法、架构和代码进行专业判断，主动发现整体体验问题，并在模块职责范围内自主设计和完善。

已经确认的玩法决策以 [DECISION_LOG.md](DECISION_LOG.md) 为准。若认为某项已确认决策不合理，应提出有证据的变更建议，说明理由、影响和替代方向，交由项目负责人裁决，不得因局部实现方便而擅自改变。

## 9. 成品成功的判断

我们不以系统数量、代码规模或文档数量衡量游戏是否成功。目标成品应当做到：

- 玩家能够理解自己经营的公司、作品和委员会之间的关系；
- 公司资源有限，玩家需要作出有意义的经营选择；
- 不同员工、合作模式和经营策略能够产生不同结果；
- 每部作品的制作过程有变化，而不是机械填充进度；
- 制作委员会确实连接具体作品的投资方与产业资源；
- 公司成长能够改变未来的经营机会和制作能力；
- 随机性带来值得记住、能够理解和复盘的经营经历；
- 玩家愿意为了下一部作品继续经营下去。

我们希望玩家在十年结束时能够感受到：

> 这家公司是我一点点经营起来的。
>
> 这些作品是我组织团队制作出来的。
>
> 这些员工陪伴公司走过了很多年。
>
> 我经历过失败，也抓住过机会。
>
> 十年过去，我建立了一家真正属于自己的动画公司。
