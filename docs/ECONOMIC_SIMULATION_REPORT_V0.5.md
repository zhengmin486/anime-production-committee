# 经济模拟报告 V0.5（工资、加班、阶段外包与非 BD 收入）

> 历史资料说明：本文记录旧版 V2/V3 契约、旧五阶段制作模型或当时的研究建议，不代表当前目标玩法。现行决策以 [DECISION_LOG.md](DECISION_LOG.md) 为准：项目级公共制作 + 单集六阶段、工作项依赖并行、核心员工每周严格单项目分配、多项目并行及限时资金危机。本文中的旧阶段、资源分配和资金规则仅作为历史证据/旧实现迁移参考，不得直接作为新架构依据。


> 状态：在 V0.4 动态工作量模型上，加入员工周薪、加班费、分阶段外包成本与委员会非 BD 渠道收入。每种策略 500 次，共 2,000 次模拟。运行日期：2026-11-23。本文数值均为首轮实验参数，不是行业报价或最终平衡结论。

## 1. 本轮新增参数

### 员工工资与固定运营费

| 参数 | 本轮取值 |
|---|---:|
| 初始核心员工 | 4 人 |
| 每人周薪 | 5 万日元 |
| 核心员工周薪合计 | 20 万日元 |
| 每周固定运营费 | 20 万日元 |
| 基础固定现金支出 | 40 万日元/周 |
| 加班工资倍率 | 1.5 倍 |
| 加班产能上限 | 常规工时的 20% |

每周固定运营费 20 万沿用 V1 数值提案；员工工资单独计算。此前模拟器临时使用的 68 万/周固定成本不再沿用，因此本轮结果不能直接与 V0.4 的期末现金比较。

加班按“额外加班工时 × 正常工资 × 1.5”计费。模型只在剩余阶段工作量按剩余工期推算后，发现常规产能不足时启用加班。20%是为了让模型可运行而暂定的加班上限。

### 分阶段外包

外包份额表示该阶段总工作量中交由外部团队完成的比例。外包会增加阶段吞吐，同时按外包工作量和单位价格计费。

| 阶段 | 外包占比 | 外包单价（日元/工作量单位） |
|---|---:|---:|
| 脚本 | 20% | 8,000 |
| 分镜 | 25% | 10,000 |
| 原画 | 45% | 14,000 |
| 动画检查 | 30% | 7,000 |
| 后期 | 35% | 9,000 |

本轮内部团队常规产能暂定为 70 工作量单位/周；外包按阶段占比补充产能。以上外包比例和单价均为游戏经济模型的起始估值，不代表现实市场报价。

### 委员会非 BD 收入

收入按“合同预算 × 渠道基准比例 × 渠道适配度 × 商业表现倍率”计算，再乘玩家投资比例。

| 渠道 | 适配度为100时的毛收入基准 |
|---|---:|
| 出版社 | 合同预算 × 25% |
| 玩具 | 合同预算 × 35% |
| 音乐 | 合同预算 × 15% |
| 电视播出 | 合同预算 × 30% |

- 每个委员会项目暂按开放 2 个渠道处理，从上述 4 个渠道中抽取。
- 普通适配度暂按 20–40 抽样。
- 商业表现倍率：D 0.3、C 0.6、B 1.0、A 1.5、S 2.5。
- 玩家取得的非 BD 收入 = 渠道毛收入 × 玩家投资比例。
- 非 BD 收入不再额外扣除 BD 的综合成本。承制模式不取得这部分收入。

渠道数量目前是为了跑通经济模型的简化假设；正式游戏仍由委员会成员决定开放哪些渠道。

## 2. 运行设置

- 经营周期 520 周；每种策略 500 次，共 2,000 次。
- 固定 seed：`20261123`。
- 初始资金 5,000 万日元。
- 策略：全部承制、委员会固定 10%、委员会固定 50%、委员会固定 100%。
- 保留 V0.4 的五阶段工作量、动态合格线、打磨、延期、低完成度交付与违约规则。
- 运行命令：`python scripts/economic_simulator.py`。

## 4. 初步观察

1. **成本开始进入模型。** 现在项目制作不再只有固定运营费，还会持续支付核心员工工资、按阶段发生外包费用，以及必要的加班费用。
2. **外包是产能与成本的交换。** 原画外包比例最高，单位价格也最高；它能缓解关键阶段产能压力，但会明显增加项目成本。
3. **非 BD 收入开始体现委员会投资的收益差异。** 委员会10%和50%策略分别取得平均约 3,557 万、8,935 万日元的非 BD 分账收入。投资比例越高，分账份额越高，但本金风险也更大。
4. **委员会50%出现一定破产压力。** 500 次中破产率为 6.6%，但不能直接判断风险已经平衡；固定比例策略仍不能代表玩家动态调整投资比例的真实玩法。
5. **委员会100%破产率仍主要受开局资金门槛影响。** 玩家需要先承担投资额，固定100%策略无法像真实玩家一样先承制积累现金。
6. **本轮现金结果仍然偏乐观。** 核心员工数量固定为4人，临时员工招聘、岗位能力差异、疲劳、成长和更复杂的项目成本仍未接入。非 BD 渠道也只是按普通适配度抽样，尚未覆盖高适配企划和玩家实际选择。

## 5. 测试情况

- 自动化测试：9/9 通过。
- 覆盖评分档位、固定 seed 可复现、承制不延期、委员会延期次数、动态阶段合格线、外包成本、加班上限、非 BD 收入模式边界与工资计算。
- 模拟器不依赖第三方 Python 库。

## 6. 下一步需要校准

1. 员工模块确认核心员工数量、临时员工招聘和实际岗位产能后，替换“4人固定团队、70单位/周”的占位模型。
2. 确认外包比例是玩家可调、企划固定，还是受员工能力/工期压力触发；本轮暂时视为每阶段固定比例。
3. 逐项校准外包单位价格与外包产能，不应只调价格而不考虑交付效率。
4. 正式委员会成员和渠道数据确定后，替换“每项目随机开放2个渠道”的简化规则。
5. 接入项目小/标准/大规模档位后，再检查同类型项目规模差异和利润空间。
6. 本轮所有策略都使用固定投资比例；下一轮应考虑“先承制积累、再动态选择委员会比例”的策略，避免把固定100%策略的结果误读为玩法结论。

**结论：** 本轮已把用户指定的 5 万日元/人/周工资、1.5 倍加班、分阶段外包和非 BD 收入纳入模型。成本与收益结构比 V0.4 更完整，但外包价格、外包比例、非 BD 渠道收入和内部产能仍是待验证的实验参数。当前结果适合继续讨论，不应直接作为最终数值定案。
