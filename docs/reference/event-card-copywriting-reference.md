# 事件卡文案独立参考：电视台探班

> 用途：团队内部文案质量参照与后续复核依据。  
> 性质：独立参考稿，不是规则变更，不是对内容作者的预设答案，也不要求其他事件照搬文风。  
> 来源：`content/events/station_visit.json`（归档时 main 分支版本）。

## 一、修订后的独立参考稿

| 字段 | 参考文案 |
|---|---|
| `description` | 电视台制片人前来探班。看过制作素材后，他对团队当前的制作状态表示满意。 |
| `foreshadow` | 发行方最近频繁询问制作进度。 |
| 接待选项 `risk_hint` | 接待需支出 60,000 资金，并占用半天工期；可提升团队士气，并提高动画阶段质量。 |
| 婉拒选项 `risk_hint` | 无需额外支出，但会错过这次关系维护机会。 |

## 二、文案审查依据

1. **不扩写事实**：可以润色表达，但不擅自增加人物意图、商业承诺或事件经过。
2. **线索忠于原数据**：`foreshadow` 应表达已有信息，不另写未经数据支持的剧情。
3. **选项效果有据可查**：成本、时间占用和效果应能对应事件数据中的 `cost`、`effects` 等字段，不凭空承诺收益。
4. **区分叙事与机制**：文案可以让事件更自然，但不能借文案改变触发条件、效果范围或规则语义。

## 三、源事件数据对应关系

- 事件：`station_visit` / 电视台探班。
- 接待选项：`cost = 60000`；即时士气 `+6`；动画阶段质量 `+1`。
- 婉拒选项：`cost = 0`；无效果字段；原始风险提示为“错过关系维护”。
- 原事件描述：电视台制片人来探班，看完素材后对团队状态满意。
- 原预告线索：发行方最近频繁询问制作进度。

## 四、使用边界

本稿只用于对照文案是否准确、自然、具体。它不是唯一正确写法，也不代表必须采用相同句式。若源事件数据或规则发生变化，应先重新核对源数据，再决定是否沿用本稿。
