# 事件卡片库（WP7 内容层样例）

- 整理：@pyxz0（事件系统），内容所有权仍归 @Muchbv（#13）
- 依据：`docs/CORE_GAMEPLAY_WORKSTREAM_BREAKDOWN_2026-11-24.md` WP7「事件内容与风险表达（仅内容层）」
- 定位：**内容层样例**，把已有 8 条示例从数据结构改写成可读的事件卡片，供内容协作者扩写与替换；不定义触发概率、优先级算法或跨模块写入。
- 对应数据：`docs/event_catalog.example.json`（字段校验器 `scripts/validate-event-catalog.mjs`）

## 使用方式

1. 一张卡片对应一个事件定义，`id` 与目录一致，便于双向核对。
2. 「触发方向」只写玩家可理解的处境，不写阈值和概率——阈值属于定义表，由系统负责人维护。
3. 每个选项必须写清：确定成本、可能收益、风险方向、适用情境。**不允许出现无条件最优选项。**
4. 卡片不写代码字段（`scope`/`target`/`value`），这些在数据文件里；卡片只描述玩家看到的东西。

## 卡片

### C-01 关键镜头返修（`key_cut_rework`）

| 项 | 内容 |
| --- | --- |
| 极性 / 层级 | 负面 / 普通 |
| 适用阶段 | 原画、动画检查 |
| 触发方向 | 本阶段画面质量明显低于作画监督的验收线 |
| 处理期限 | 无 |

**前因或风险线索**：作画监督连续退回同一段镜头；检查记录里出现「构图不稳」「动作衔接跳帧」。

**情境**：本阶段有几卡关键镜头没有达到作画监督的要求。现在返修还来得及，但要多占用一周的人手。

| 选项 | 确定成本 | 可能收益 | 风险方向 | 适用情境 |
| --- | --- | --- | --- | --- |
| 按现状推进 | 无现金支出；团队士气 −3 | 保住本周进度 | 质量缺口留到成片，影响交付评价 | 工期紧、现金薄，且后续阶段还有补救空间 |
| 抽调人手返修 | 18 万；疲劳 +6 | 本阶段质量 +4 | 疲劳累积可能在后续周触发人员事件 | 现金充裕、作品目标是冲质量分 |

**内容备注**：两个选项分别代表「保进度」与「保质量」，没有一方全面占优。

### C-02 作画进度落后（`schedule_slip`）

| 项 | 内容 |
| --- | --- |
| 极性 / 层级 | 负面 / 普通 |
| 适用阶段 | 原画、动画检查 |
| 触发方向 | 距交付周数已很紧，进度仍落后于计划 |
| 处理期限 | 无 |

**前因或风险线索**：周报里连续两周「完成量低于计划」；现场开始出现「先把能交的镜头交出去」的说法。

**情境**：离交付只剩三周，作画进度明显落后于计划。继续按原节奏推进很可能赶不上截止周。

| 选项 | 确定成本 | 可能收益 | 风险方向 | 适用情境 |
| --- | --- | --- | --- | --- |
| 维持原计划 | 本阶段质量 −3 | 不额外花钱、不额外压人 | 大概率仍赶不上，转为违约交付 | 已经接受低质量交付，只想止血 |
| 全员赶工 | 12 万；疲劳 +8 | 本周进度 +120 | 疲劳飙升，后续周更容易出人员事件 | 现金允许、且只差一小段就能追上 |
| 向委员会申请延期 | 25 万；士气 −4 | 争取更多制作周 | 承制项目不可用；委员会项目只能用一次 | 委员会项目、作品质量值得救 |

**内容备注**：「延期」只对委员会项目开放，承制项目该选项显示禁用原因，不要写成「花钱就能延期」。

### C-03 原画师过劳（`animator_exhaustion`）

| 项 | 内容 |
| --- | --- |
| 极性 / 层级 | 负面 / 普通 |
| 适用阶段 | 原画、动画检查、后期 |
| 触发方向 | 核心成员疲劳已到危险区间 |
| 处理期限 | 无 |

**前因或风险线索**：某位原画师连续加班；作画速度开始下滑，返修率上升。

**情境**：主力原画师连续加班，本周已经出现明显的状态下滑。再压下去可能影响整段作画质量。

| 选项 | 确定成本 | 可能收益 | 风险方向 | 适用情境 |
| --- | --- | --- | --- | --- |
| 让他自己调整 | 士气 −6 | 不花钱、不占外部产能 | 疲劳没降，下一周可能再触发 | 现金紧、且本周没有关键镜头压在他身上 |
| 临时找外包接手 | 32 万 | 把工作量转出去 | 外包质量参差，本阶段质量 −2 | 现金允许、且外包方向匹配 |

**内容备注**：这是「人」的问题，不是「钱能全解」的问题；外包有质量代价，不能写成纯增益。

### C-04 预算见底（`budget_overrun`）

| 项 | 内容 |
| --- | --- |
| 极性 / 层级 | 负面 / 普通 |
| 适用阶段 | 分镜、原画、动画检查、后期 |
| 触发方向 | 账面现金已接近下周强制支出的底线 |
| 处理期限 | 无 |

**前因或风险线索**：周报现金连续下降；财务提示「下周工资与制作费可能不足」。

**情境**：账面现金已经压到低位，下周的工资与制作支出可能不够。制作组在等一个说法。

| 选项 | 确定成本 | 可能收益 | 风险方向 | 适用情境 |
| --- | --- | --- | --- | --- |
| 压缩开支硬撑 | 士气 −5 | 不增加负债 | 士气下滑，后续事件更密集 | 只差一两周就能回款 |
| 向投资方预支部分制作费 | 9 万手续费 | 现金 +45 万 | 预支会在交付结算时抵扣，未来收入变薄 | 项目质量值得保、且能撑到交付 |

**内容备注（待调整）**：预支属于「事件收入」，当前分类未定；迁移到新模型时要么新增收入科目，要么改成「降低本周制作投入 + 质量代价」。卡片先保留玩法意图，不锁定数值。

| 适用阶段 | 分镜、原画 |
| 触发方向 | 本阶段质量已经不错，团队有余力尝试更大胆的表达 |
| 处理期限 | 无 |

**前因或风险线索**：演出在会议里反复提到一个没被采用的调度方案；分镜稿上有多处临时加的批注。

**情境**：演出提了一个更大胆的调度方案，能把这一段的气氛再推高一层，但需要额外的人手配合。

| 选项 | 确定成本 | 可能收益 | 风险方向 | 适用情境 |
| --- | --- | --- | --- | --- |

| 按原方案走 | 无 | 稳定推进 | 错过一次质量跃升 | 工期优先、或现金已经很紧 |

**内容备注**：正面事件也要有成本，不能是免费增益。

### C-07 作画监督病倒（`director_illness`，重大）

| 项 | 内容 |
| --- | --- |
| 极性 / 层级 | 负面 / 重大 |
| 适用阶段 | 原画、动画检查 |
| 触发方向 | 核心成员疲劳长期处于高位后倒下 |
| 处理期限 | 无（迁移时建议加 2 周期限） |

**前因或风险线索**：作画监督连续两周通宵；此前已有「检查进度堆积」的提示。这是**有预兆**的重大事件，不应无征兆发生。

**情境**：作画监督在连续两周通宵后倒下，医生要求至少静养两周。他手上还压着后半个阶段的检查工作。

| 选项 | 确定成本 | 可能收益 | 风险方向 | 适用情境 |
| --- | --- | --- | --- | --- |
| 让副手顶上 | 本阶段质量 −5、本作质量 −2 | 不花钱、项目继续 | 质量缺口贯穿到交付 | 现金极紧、且作品目标本来不高 |
| 请退休前辈回来救场 | 30 万；疲劳 +8 | 本阶段质量 +2 | 老手回归只能救急，疲劳仍在团队身上 | 质量路线、现金允许 |
| 把检查工作分包出去 | 50 万 | 项目质量仅 −1 | 外包方不熟悉本作风格，返修风险 | 现金充裕、且外包方向匹配 |
| 用掉委员会延期 | 25 万；士气 −4 | 争取时间 | 承制不可用；委员会只能用一次 | 委员会项目、且只差时间 |

**内容备注**：四个选项覆盖「省钱 / 保质量 / 买时间」三条路线，没有一项全面占优；这是重大事件该有的分量。

| 适用阶段 | 动画检查、后期 |
| 触发方向 | 项目已积累一定外部关注度 |
| 处理期限 | 无 |

## 风险提示文案库

按触发指标分组，供周报与事件前兆复用。文案只描述现象，不泄露数值。

| 指标 | 预警短句 |
| --- | --- |
| 阶段质量偏低 | 「作画监督连续退回同一段镜头」／「检查记录里出现构图不稳」／「这段的完成度比前几卡低一档」 |
| 疲劳偏高 | 「某位核心成员连续加班」／「作画速度开始下滑」／「现场开始靠咖啡和外卖撑」 |
| 工期压力 | 「完成量连续两周低于计划」／「距交付只剩三周」／「排期表已经排到交付后」 |
| 现金压力 | 「账面现金接近下周支出底线」／「财务提示下周工资可能不足」／「外包尾款还没结」 |
| 士气偏低 | 「会议上没人提新方案」／「有人开始准点走」／「返修单没人愿意接」 |

## 选项设计说明

1. **每条事件至少两条路径**：一条保现金/进度，一条保质量/关系，代价不同且不可同时拿到。
2. **确定成本必须写在选项上**：现金、疲劳、士气、质量，至少写清一项；不要把确定损失藏进描述。
3. **风险只写方向**：可以说「可能触发人员事件」，不要写「30% 概率触发」。
4. **跨模块选项要标依赖**：延期只对委员会开放、外包依赖供应商池；实现不到位时显示禁用原因，不写成可用。
5. **重大事件要有前兆**：至少在触发前一周给出可读线索，避免「无征兆毁项目」。
6. **正面事件也要有代价**：免费增益会让玩家无脑点，失去决策意义。
