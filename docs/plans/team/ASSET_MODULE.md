# 素材模块交付说明

- 模块负责人：@pyxz0
- 跟踪议题：[#9 初期三图授权与接入准备](../../issues/9)
- 依据：现有 `docs/ASSET_CATALOG.md`；本文件是交付边界与验收清单，不替代素材目录中的逐图来源记录。
- 状态：待负责人推进；美术验收不等于授权通过，也不代表已接入游戏。

## 本轮目标

完成初期三张图片的授权核查、可共享资源整理和必要接入准备。先核查授权，再决定是否把图片放入公开仓库；不能因图片已经生成或视觉检查通过，就默认可以商用或公开分发。

## 当前素材范围

只处理以下三张初期素材，不扩展完整素材库：

| 素材 | 本地评估文件 | 目标尺寸 | 用途 |
| --- | --- | ---: | --- |
| 办公室背景 | `.tools/asset_review/early_development/backgrounds/studio_office.png` | 1280×720 | 公司主场景背景，中央留白供 UI 叠加 |
| 制作人头像 | `.tools/asset_review/early_development/characters/producer.png` | 512×512 | 人物卡片与角色介绍的头像基准 |
| 制作示意图 | `.tools/asset_review/early_development/production/colored_frame.png` | 960×540 | 单张原创动画画面示意，不代表完整制作阶段系统 |

另有 6 张已生成备用图，见 `docs/ASSET_CATALOG.md`。它们保留备用，不是本轮必须接入的交付项。

## 已确认的美术要求

- 温暖、协调、可用于游戏界面的日式 16-bit 像素风插画。
- 不接受摄影、3D、普通矢量插画或明显风格冲突。
- 不再恢复旧版固定逻辑网格、24 色、禁抗锯齿等已取消要求。
- PNG；按用途保持正确宽高比，不拉伸。
- 文件名使用英文小写和下划线。

## 负责人交付内容

1. **逐图授权核查**：记录图像生成工具/服务的实际适用条款，确认商用、修改、分发、署名要求，以及是否允许将图片放入公开 GitHub 仓库。无法确认的部分明确标为阻塞，不推断授权。
2. **共享方式**：仅在授权和公开共享范围明确后，将获准图片放入 `apps/web/public/assets/` 对应目录。不得上传整个被忽略的 `.tools/`，不得使用临时 URL。
3. **素材目录更新**：在 `docs/research/ASSET_CATALOG_EARLY.md`（旧路径 `docs/ASSET_CATALOG.md`）中逐项更新来源、条款、尺寸、格式、文件路径、审核状态和授权状态；必要时更新 `docs/asset_prompts.json`。
4. **接入准备/接入**：若授权通过，与前端协商使用位置；接入时提供真实浏览器截图和验证结果。
5. **阻塞报告**：若原图不可共享或授权链无法确认，写明具体缺少什么证据、当前保留状态及可行替代方案。不得伪造许可结论。

## 明确不做

- 不新增海报、分镜、原画、中间稿、道具、特效或音频。
- 不批量生成更多员工头像，不扩展完整素材库。
- 不为绕过授权问题修改 `.gitignore` 或上传整个临时审核目录。
- 不把“视觉通过”写成“法律授权通过”或“正式可商用”。

## 验收标准

- [ ] 三张图片逐项有来源及适用条款证据。
- [ ] 商用、修改、分发、署名和公开仓库共享权限分别有明确结论；未知项标阻塞。
- [ ] 获准资源可从仓库正常取得，路径稳定，无私有临时 URL。
- [ ] 图片尺寸、格式、体积、宽高比和文件完整性已核对。
- [ ] 若接入 UI，完成 375 / 768 / 1440px 浏览器检查，并提供截图。
- [ ] 接入时 `npm run build`、`npm run verify:dist`、`npm run test:browser` 有真实结果；未执行的命令明确说明。
- [ ] 授权未通过时保持未入库、未接入状态，不关闭为“素材接入完成”。

## 协作边界

- 本模块负责人负责素材方案、授权证据、资源整理及素材相关接入。
- 页面结构或共用前端改动先与前端负责人协调。
- 不修改核心共享文件：`game_core.cpp`、`game_rules.hpp`、`embind.cpp`、`gameV3.ts`、fixtures、browser test 和存档格式。
- 交付以 PR 和可核查证据为准；本文件不表示素材已上传或授权已完成。
