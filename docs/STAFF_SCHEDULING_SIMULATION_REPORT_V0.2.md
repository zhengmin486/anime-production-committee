# 员工排班模拟实验报告 V0.2

## 本轮修正

V0.1 结果不能直接用于比较，修正了以下偏差：

1. \`dynamic_pair_deadline\` 未被识别为动态策略，之前实际锁定了阶段人员。
2. Deadline 生产速度系数顺序未严格按 \`game_core.cpp\` 执行。
3. Deadline 阶段质量漏乘 \`policy.quality=800\`。
4. 阶段质量累计改为 C++ 相同的整数计算；最终作品质量改用 \`quality_weights={150,200,250,200,200}\`，不再简单平均。
5. 增加逐周人员分配记录与阶段内人员组合变化次数。

## 实验条件

- 员工：上传的 \`staff_templates.json\`，15 人（12 核心、3 临时），属性不修改。
- 五阶段串行；每阶段工作量统一设为 30、60、90、120，进行敏感性实验。
- 总工期上限 14 周。
- 动态策略每周按当前能力、专业适配、士气、疲劳重新选择当周产能最高的 2/3 人；固定策略在阶段开始时锁定人员。
- 不包含特性、潜力成长、临时员工项目费、事件、外包、阶段并行和正式违约结算。所有员工（包括临时员工）均可参与，但临时费用不计入现金流。
- 规则系数和整数计算顺序按 \`game_rules.hpp\`、\`game_core.cpp\`；工作量与 14 周期限仍是实验输入，不是正式平衡参数。

“换人次数”指同一阶段相邻周人员组合发生变化的次数。未完成项目展示截至第 14 周的累计质量，不代表可交付作品质量。

## 结论

1. 动态选人确实发生轮换，但当前人物属性与疲劳规则下，轮换没有稳定提升质量或完工率。
2. 工作量 30 时阶段太短，动态双人没有换人；该参数不足以验证动态调度价值。
3. 工作量增加后，动态双人/三人开始轮换，但换人不保证质量更高。工作量 60 时动态双人和固定双人均完成 180 工作量，动态质量略低；工作量 90 时动态策略多完成少量工作，质量基本持平。
4. 当前动态算法只优化“本周产能”，没有考虑阶段质量、跨阶段人员培养、临时员工费用和未来阶段人力储备。它是贪心基线，不是最终游戏排班 AI。
5. Deadline 策略提速同时降低质量系数、增加士气损耗；Deadline 全员最快，但临时员工费用未计入，不能据此判断经济最优。

## 下一轮建议

不要直接加大疲劳惩罚来制造动态轮换优势。下一轮比较三种目标函数：

- 纯产能最大化：当前基线。
- 质量优先：满足工期前提下最大化阶段质量。
- 工期/质量折中：显式权衡完工率、质量和人员疲劳。

之后再决定动态排班是否应该成为正式玩法，还是只作为玩家手动配置的辅助推荐。
