## 模块目标

在制作过程中提供与项目状态有关的正面机会和负面异常，让玩家在收益、质量、进度、资金和人员压力之间做选择。事件是当前项目的附属机制，不是独立的公司事件系统。

## 已确认规则（不可自行改写）

1. 首版只做依附具体制作项目的事件；事件必须关联作品、阶段、员工、合作方或项目状态。
2. 同时包含正面机会与负面异常；正面机会可接受或放弃，负面异常需要处理或承担后果。
3. 触发采用表现触发 + 随机触发；表现依据进度、阶段质量、疲劳等真实状态。
4. 每项目每周最多触发一个；同项目同周多个候选按固定优先级选择，不额外消耗随机种子。处理完当周不再为该项目触发第二个。
5. 不同项目可同周触发；多个未处理事件保留在 `pending[]`，可按任意顺序解决。数组非空时禁止推进周，全部解决后才能继续。
6. 事件在既定周结算时序的事件检查节点触发；公司运行、项目未交付且当前阶段 active 时才检查。阶段切换、交付或终局后不追加。
7. 同类事件设置冷却或重复限制；重大事件同一项目最多触发一次。不同重大事件可先后出现。
8. 效果持续时间分即时、阶段、项目三种；不做跨项目永久效果，不追溯修改已结算阶段。普通事件通常影响当前或一个后续阶段，重大事件可影响多个后续阶段。
9. 事件选项依性质配置，不要求每个事件支持所有选项。负面处理候选包括放弃、加班、应急外包、延期；正面机会可接受/放弃。M2 未实现的外包/延期及任何非零 `funds` 效果返回 `NOT_IMPLEMENTED`。
10. 每个事件实例只选择一次，不可撤销、重试或刷取；`resolve_event.event_id` 使用 `instance_id`，失败可产生后续影响，但仍受每项目每周最多一个事件限制。
11. 确定代价必须明确展示；可展示风险等级/预期，不必公开精确概率。不能把确定损失伪装成未知风险。
12. 重大事件固定且数量较少，可有前置条件和预兆；普通事件按员工、阶段、合作方和项目状态组合触发。
13. 应急外包复用员工模块的供应商系统；延期复用既有规则：承制不可延期，委员会最多一次延期。
14. 事件不能修改合同目标/条件，不能绕过员工、供应商、财务、阶段配置或公司终局规则；不能直接判定项目失败或公司倒闭。
15. 重大事件纳入作品履历，记录事件名称、处理方式和最终结果；普通事件按需汇总，不逐条堆积。历史事件不影响下一部作品触发概率。

## 模块分工

### 系统机制与实现：@pyxz0

负责事件触发、优先级、冷却、暂停/恢复、选项可用条件、效果结算、超时规则和系统接入。系统负责人确定事件数据所需字段、可调用的既有系统能力及效果约束。

### 具体事件内容：@Muchbv

负责具体事件的题材、背景、人物/合作方情境、事件文本、选项文案和轻量剧情表达，并按系统负责人给出的事件数据结构提交内容提案。具体事件不能自行引入新状态、新效果类型或绕过已有规则；需要新增机制时先提出需求，由系统负责人评估，涉及全局规则或契约时交 zm 决定。

## 模块负责人的交付内容

1. **事件机制配置**：支持固定重大事件与普通事件，提供背景、分类、适用阶段、触发条件、重复限制、可见信息等数据接口。
2. **触发配置**：表现触发条件、随机触发条件、优先级、冷却、重复限制及确定性随机消耗说明。
3. **选项与效果**：每个事件支持哪些选项、确定代价、成功预期/风险等级、失败后果、即时/阶段/项目效果。
4. **超时规则**：适用事件的处理期限、超时升级结果；正面机会通常不设期限，按事件性质说明例外。
5. **跨系统调用清单**：逐项说明事件如何调用员工、供应商、资金、阶段配置、延期与履历能力；不重复实现这些系统。
6. **测试夹具**：覆盖表现触发、随机触发、同周优先级、冷却、重大事件一次性、暂停/恢复、超时、阶段效果和失败后果。
7. **履历输入**：明确重大事件需要向作品履历提供的事件名称、处理方式、结果字段；由 zm 的跨系统集成层统一写入历史。
8. **参数建议**：触发阈值、概率、费用、成功率、效果等给推荐值、理由、影响面和验收方法，全部标注 `TODO(待定)`，交负责人审查。

## 明确不做

- 不做独立公司级事件、跨项目永久事件效果或下一项目历史事件加权。
- 不另建供应商、员工、财务、延期或合同系统。
- 不修改合同目标、交付标准、合同条件或投资方承诺。
- 不绕过阶段配置锁、财务限制或公司终局判定。
- 不直接写入公司声望、公司状态或作品历史；输出变化量/履历输入，由对应系统统一写入。
- 不把事件数量、触发概率或数值当作已确认；需通过提案审查。
- 轻量剧情仅作为既有员工、企划、事件和经营节点的内容表达，不建立独立剧情系统。

## 交付与验收

- [ ] 正面与负面事件均有可玩的代表案例。
- [ ] 表现触发与随机触发均能覆盖；同种子同操作可重放。
- [ ] 每项目每周最多一个，多项目可同周触发；所有实例保留、任意顺序解决，pending 非空时禁止推进。
- [ ] 事件触发暂停周推进，处理后可恢复。
- [ ] 同周候选优先级固定，不额外消耗随机种子。
- [ ] 即时/阶段/项目效果边界正确，不追溯已结算阶段。
- [ ] 重大事件同项目不重复，普通事件冷却/重复限制有效。
- [ ] 选项的确定代价清晰；应急外包和延期遵守既有模块规则。
- [ ] 事件不能绕过合同、财务、阶段或终局边界。
- [ ] 重大事件履历输入可交由集成层写入；普通事件按需汇总。
- [ ] 提供真实测试命令与输出；未执行项如实标注。
