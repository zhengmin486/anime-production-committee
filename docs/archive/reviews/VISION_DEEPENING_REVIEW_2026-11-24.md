## 2. 对上一轮助手建议的复核与修正

上一轮助手提出了“判断密度”定位、反对把 A/S 档一刀切锁定为委员会、待处理项按类型设计、优先建立产能标定、对 pro-rata 和立项一次性预付表示倾向，以及把经营循环整理成机会—押注—制作—结果—积累。

复核后保留和修正如下。

### 2.1 核心定位：保留，但以愿景原文为准

**结论：保留。**

上一轮“判断密度游戏”的概括与愿景 v1.0 §1.1 一致，但正式表达应回到“为下一部押什么反复权衡，而不是为这一周怎么排反复操作”。

上一轮提出的经营循环图与愿景 v1.0 §3 的三层循环并不冲突，但不必再新增一套平行循环。后续应检查每个系统是否进入现有循环，并明确它制造的玩家决策、代价、结果和长期影响。

### 2.2 D-01：A/S 档仅委员会开放

**结论：不建议直接采纳硬性档位锁定。**

理由：

1. PR #44 候选愿景 §2.3 已写明：普通企划可选择承制或委员会模式，原创企划必须采用委员会模式。
2. 候选框架 §7.1 也保留普通企划两种模式可选的口径。
3. “A/S 只能委员会”会把商业选择直接变成档位门禁，可能压缩高档企划在资金、渠道、风险和公司能力不同条件下的经营选择。
4. 真正需要解决的是“永远承制是否成为最优解”，而不是强制玩家进入委员会。

建议先通过经济模型和企划池分布验证承制路线是否支配。若仍然支配，优先调整高档承制项目的出现频率、合同毛利、委托方条件和商业表现奖励，而不是直接封死合作模式。特殊企划可以有明确的委员会专属条件，但不把 A/S 档整体绑定为委员会。

### 2.3 D-02：默认处置与每周一个待处理项

**结论：采纳问题方向，不直接采纳统一默认惩罚。**

需要分清三件事：

- **展示上限：** 候选 DEC-PLAY-006 已规定推进前最多呈现一个待处理项，优先级为产能缺口、关键交付节点、失效的定向目标。
- **事项产生：** 不能因为界面每周只显示一个，就推导出游戏世界每周只能发生一个问题；多项目的风险和触发仍应独立存在。
- **超时处置：** 玩家不处理某事项时，系统如何结算，必须按事项类型定义，不可统一处理。

建议将事项分成至少三类：必须处理的阻塞项、有明确期限的机会/节点、可自动恢复或失效的提醒。每类分别定义有效期、默认结果和是否阻塞周推进。

默认结果不得绕过 DEC-PLAY-002：系统不能静默新增招聘、外包、融资或其他未授权的资金承诺。轮转只适合解决同优先级事项的展示公平性，不能覆盖明确的紧急程度。

### 2.4 E-01：经济标定流水线

**结论：采纳，列为当前最高优先级工程准备。**

本轮对蓝图进行了直接计算：

- TV 蓝图：12 集。
- 项目级公共制作：6 项，共 325 工作点。
- 单集模板：14 项，每集 596 工作点。
- 12 集总计：325 + 596 × 12 = **7,477 工作点**。
- 蓝图注明 1 点 = 1/100 人周，因此结构换算为 **74.77 人周**。
- 若假设 3 名员工每周均能提供 100 点且持续满负荷，理论除法结果约 **24.92 周**。

**这不是正式工期结论。** 蓝图 notes 明确写明当前数值为占位量级样例，用于结构校验，不作为平衡依据。上述 24.92 周也没有证明员工实际产能、疲劳、专业适配、监督、磨合、外包、质量门槛、返工和依赖并行都已被正确计入。

PR #44 候选决策 DEC-PROD-006 已明确工期应由集数与单集六阶段工作量反推，不得由占位产能反向决定；其候选目标为 520 周交付 10–18 部，标准 TV 工期实验起点约 30 周。当前 24.92 周与该目标接近，但不能据此判定目标已经验证。

建议按两层推进：

1. **生产能力验证：** v4 内核读取正式蓝图，输出不同规模作品的工作量、工期、并行度、人员需求和瓶颈。
2. **经济参数标定：** 在生产能力可信后，再调整工资、制作成本、外包报价、制作费毛利、保证金、预付、配当和后端窗口收入。

不得先调经济参数，再用未校准的产能模型证明经济结构正确。

### 2.5 DEC-FIN-006：元金优先 vs pro-rata

**结论：撤回上一轮对 pro-rata v1 的倾向，不建议现在改登记册。**

上一轮倾向 pro-rata 的依据是“首版只有玩家一个大投资方、与预付比例分配一致、实现更便宜”。复核后认为这个理由不足以推翻 PR #44 候选登记册已经写入的“元金优先回收、分阶段配当”。

需要比较的不是一个抽象分账算法，而是完整现金流：

- 多个投资方的投资比例不同；
- 交付后短期、半年、长尾分期到账；
- 收入不足以覆盖所有应收时如何分配；
- 项目终止、失败或中止时未结应收如何处理；
- 投资本金回收完毕后，利润分成如何开始；
- 公司对自身投资位的应收如何与现金、项目账、公司账对齐。

建议先保留候选 DEC-FIN-006 的元金优先方向，建立元金优先与 pro-rata 两套对照模型，再以可解释性、策略差异、账务复杂度和失败路径决定是否变更。没有比较结果前，不应因“看起来更便宜”就替换已写入候选登记册的方向。

### 2.6 配信预付：立项约定与现金到账时点必须分开

**结论：上一轮“立项一次入账”的表述过早，修正为待明确的现金流口径。**

愿景候选 §2.3 和 DEC-FIN-004 说明预付在立项期谈定，并且预付可以在制作期按投资比例分配。这能证明**合同条件在立项期确定**，但不能单独证明现金必须在立项当天一次性全部到账。

需要分别定义：

1. 报价/合同在何时确定；
2. 应收何时成立；
3. 现金何时到账；
4. 到账后如何按投资比例分配；
5. 预付是否影响后端分成或只改变预付与后端的比例。

若首版为降低复杂度采用立项一次到账，应明确这是首版现金流简化，并通过现金曲线与策略模拟验证，而不是把“立项期谈定”解释成“立项期全部现金到账”。

### 2.7 D-04：供应商复杂度换血

**结论：撤回，维持现有供应商六属性。**

员工组织审计将供应商六属性列为 A 级既有规则：专业方向/匹配、可承接工作量、质量、速度、报价、可靠性。外包匹配度与返工风险是供应商选择的玩法内容，不应降级为单一产能数值。

PR #44 候选愿景的 12 概念预算已包含“外包与供应商”。D-04 不能以“给人才成长腾位置”为由删掉供应商机制。人才履历和代表作署名优先挂靠既有 Staff、WorkRecord 与 Archive，不新增第 13 个概念。

### 2.8 A-03 / D-12：渠道槽位与题材适配

**结论：方向成立，先做数据模型和玩法价值评估，不直接新增字段。**

候选 DEC-COMM-002 已确认“一个委员会成员对应一个商业渠道，加入即开放；渠道开放与投资比例相互独立”。因此：

- A-03 的会议室槽位化是把现有决策可视化，不应把渠道和投资比例合并为同一个滑块。
- partners[] 增加渠道类型和开放状态前，先检查委员会成员快照、渠道目录、项目渠道状态是否已有等价字段，避免重复存储。
- D-12 的题材×渠道适配可以挂靠现有成员/渠道概念，不应成为新系统。
- 适配不能做成玩家一眼查表即可得到固定最优组合；可采用窄区间、作品标签与渠道偏好共同作用，并保留一定不确定性。

### 2.9 A-06 / A-01 / A-05：成长、瓶颈与终局表现

**结论：采纳为表现方向，不新增核心概念。**

- A-01 席位成长刻度可以消费公司现金、企划投资要求和现有声望/合作条件，属于公司经营信息可视化。
- A-05 瓶颈徽章是由工作项依赖、完成度和人员/供应商分派状态推导的只读视图，不应再造一套瓶颈数值。
- A-06 终局履历墙与愿景 §11 的十年总结一致，可作为 F4/Archive 的展示目标。作品海报、关键押注、员工履历和席位成长都必须有可追溯的数据来源。
- D-05 员工署名与履历依赖 WorkRecord 成员留档和委员会成员快照，不能只做前端假数据。

### 2.10 E-03 / E-04 / E-07 / E-08：技术边界

**结论：作为后续工程设计约束采纳方向，具体契约需专项确认。**

- 预付报价应是确定性纯函数；不能消耗制作随机流，也不能因实例化顺序改变报价。
- 分期配当应收与现金分离；未到期应收不能支付工资、运营或制作费。
- 正常交付和强制交付必须走同一套配当计划登记规则，防止两条路径产生不同账目。
- 事实字段与派生字段应明确区分；规则版本兼容不能靠默认值静默掩盖缺失数据。
- M0 INV-11 约束 last_participation.week ∈ {week-1, null}，而 M1 磨合判定需要保留上次参与项目的信息。M1 文档已明确记载这一冲突，必须在 M2 开工前统一。

### 2.11 加班产能口径

**结论：标定前必须裁决，当前不写成正式规则。**

技术线发现内核口径与旧模拟器口径不一致：一边表现为加班只扣费不增加产能，另一边实验模型增加约 20% 工时。建议先明确加班究竟是：

- 只增加成本、不增加基础工作量；
- 增加产能但提高疲劳/质量风险；
- 或只对部分工作项/阶段生效。

本轮智能体倾向先采用“只扣费不加量”的内核口径作为保守基线，但这只是建议。需要在玩家体验和产能实验中验证，不能仅为对齐现有代码而定案。

## 3. 文献校准后的重要修正

### 3.1 D-04 已正式撤回

设计策略线重新核对 STAFF_ORG_AUDIT 与 STAFF_ORG_SYSTEM_DESIGN 后，确认供应商六属性是既有 A 级规则，外包匹配与返工风险本身就是经营玩法。D-04 复杂度换血撤回。

处理结果：

- 不删供应商六属性；
- 不从 12 概念预算中删除供应商；
- 人才成长、员工署名和长期履历优先复用既有 Staff / WorkRecord / Archive；
- 如需增加新概念，仍必须遵守 12 概念上限，先说明替换项。

### 3.2 工期口径存在三套数字

本轮技术线核对出：

| 来源 | TV 工期/产能口径 | 问题 |
|---|---|---|
| v4 蓝图与 M1 占位模型 | 7,477 工作点；按 3 人满负荷简单换算约 24.92 周 | 蓝图明确标注数值为占位量级，不是正式平衡 |
| 新愿景/经济实验 | 标准 TV 约 30 周作为实验起点；候选 DEC-PROD-006 目标 26–34 周 | 经济实验简化了真实生产能力 |
| 旧模拟器 | TV 约 30 周硬编码，旧生产模拟以 70 单位/周作为占位产能 | 没有从正式工作项依赖图和 v4 内核推导 |

因此当前真正的问题不是“25 周还是 30 周”，而是没有一个经过验证、统一的数据路径来推导工期。

DEC-PROD-006 的“工期由集数 × 工作量反推，不得由占位产能反向决定”必须通过 harness 和标定流程真正执行，而不只是文档声明。

### 3.3 E-04 的账务要求进一步明确

应收账本的首版范围可以控制在玩家自己的投资位，但必须满足：

1. 应收不等于现金；
2. 未到期应收不参与可用现金；
3. 到期清算发生在 due_week 对应的统一周结算预检；
4. 交付时登记配当计划；
5. 正常交付与强制交付必须调用同一登记逻辑；
6. 终止/失败项目的未结应收处理规则必须明确；
7. 账目审计覆盖应收余额、到期清算、现金余额和投资本金上限。

### 3.4 资产与数据模型风险

- 会议室与头像素材不能依赖未进入远端仓库、授权不清楚的 .tools/ 目录。
- 自生成素材管线需要记录输入、提示词/配置、生成结果和可复现方式。
- 员工代表作署名需要 WorkRecord 记录参与成员；不能仅依赖当前员工列表，因为员工可能离职或后续属性变化。
- 委员会成员快照需要在作品结算后保留；活动中的委员会解散不应导致历史记录丢失。
- partners[] 的渠道字段需要先检查现有 Project / Partnership / Archive 契约，避免重复存储“渠道开放状态”。

## 5. 复杂度预算与实现成本控制

PR #44 候选愿景 §10 / DEC-PLAY-007 将首版可交互概念上限定为 12 个。当前 12 个概念已满。

因此本轮建议按以下方式归类：

| 建议 | 是否新增概念 | 处理方式 |
|---|---|---|
| A-01 席位成长刻度 | 否 | 公司经营 HUD 的派生显示 |
| A-03 渠道槽位化 | 否 | 现有“委员会成员与渠道”的信息架构表现 |
| A-04 待处理卡片三层结构 | 否 | 周回执组件 |
| A-05 瓶颈徽章 | 否 | 现有制作状态的派生视图 |
| A-06 终局履历墙 | 否 | Archive / 终局展示 |
| A-07 场景状态表现 | 否 | 美术表现层 |
| D-03 预付两档报价 | 否 | 现有配信合同的报价选项，但会增加参数与结算分支 |
| D-12 题材×渠道适配 | 否 | 现有成员/渠道匹配规则的细化 |
| D-05 员工代表作署名 | 否 | 现有 Staff / WorkRecord / Archive 的长期记录 |
| D-13 系列继承 | 否 | 现有系列 IP 概念的规则细化 |
| E-01/E-02 标定流水线 | 否 | 开发与验证工具，不是玩家概念 |
| E-04 分期应收账本 | 否 | Finance 内部账务能力，不应单独暴露为玩家新系统 |
| D-04 供应商降级 | 不适用 | 已撤回，供应商概念保留 |

**复杂度预算不是代码模块数量上限。** 内部可以有更多模块和字段，但玩家可感知、需要理解和操作的独立概念不能无理由膨胀。任何真正新增的玩家机制都必须说明：新增了什么决策、改变什么结果、依赖什么现有概念、删掉或替换什么概念。

## 6. 建议的执行顺序

### P0：先稳住文档与工程基线

1. 处理 PR #44 与最新 main 的分支差异，明确愿景 v1.0 和系统评审采纳内容的最终合并基线。
2. PR #42 继续按已发布的产品方向审查意见修复；不把 PR 描述中的测试报告当作当前 head 已有的 CI 证据。
3. 保留 PR #45 对 PR #42 的 stacked 依赖；M1 集成另行制定方案，不在此处改 base。
4. 将本轮三方建议保留为评审提案，不覆盖现行决策登记册。

### P1：M2 前必须完成的设计口径

1. 明确 DEC-FIN-006 的配当顺序、分期应收、到期清算、失败项目未结应收处理。
2. 明确配信预付合同约定、应收成立和现金到账的时间关系。
3. 修复 INV-11 与 last_participation 的契约冲突。
4. 完成委员会成员快照、WorkRecord 成员留档和 partners[] 渠道字段的量级评估。
5. 明确加班对产能、费用、疲劳和质量的影响。

### P2：产能与经济标定

1. 建立 v4 × 蓝图产能实测 harness。
2. 以公共制作 + 单集六阶段完整蓝图计算工作量和工期。
3. 建立共享参数源，区分正式参数、实验参数和占位值。
4. 将员工、供应商、疲劳、监督、磨合、返工和并行依赖接入实验模型。
5. 再标定制作成本、工资、外包、制作费毛利、投资保证金、预付、配当与窗口收益。
6. 对照承制、低投资委员会、中投资委员会、高投资委员会的现金曲线、破产率、作品交付量和策略支配性。

### P3：表现与内容准备

1. 自生成会议室、头像与办公室场景资产，确保来源合法、远端可复现。
2. 先完成待处理卡片、瓶颈徽章和席位刻度的静态信息架构。
3. 设计危机面板与危机专用色彩 token。
4. 为十年终局履历墙定义 Archive 所需的最小事实字段。
5. 设计题材×渠道适配内容，避免固定最优查表策略。

## 7. 仍需验证的核心假设

| 假设 | 失败信号 | 验证方式 |
|---|---|---|
| 承制与委员会都能成为合理路线 | 承制始终支配，或委员会只有某一比例可玩 | 多种初始资金、项目档位和投资比例的策略模拟 |
| 玩家会在项目选择和合作模式上产生真实犹豫 | 玩家无条件选最高档或固定比例 | 纸面原型与试玩访谈 |
| 每周一个待处理项不会掩盖多项目风险 | 低优先级项目持续饥饿，玩家看不到风险 | 多项目事件与事项仲裁模拟 |
| 作品制作有足够过程感 | 玩家只看总进度，不知道作品卡点 | 真实读模型静态原型与试玩观察 |
| 员工履历能形成长期记忆 | 员工更替后历史贡献无法追溯 | Archive / WorkRecord 数据完整性测试 |
| 十年目标交付量与每周节奏匹配 | 作品太多而无法记住，或太少导致经营停滞 | v4 蓝图产能标定 + 520 周模拟 |
| 随机性可理解且不压过决策 | 相同策略结果不可解释，或随机决定全部胜负 | 固定 seed 对照、敏感性实验与试玩复盘 |

## 8. 本轮结论

1. 愿景 v1.0 的核心定位成立；本轮应深化而不是重写。
2. 三条研究线的主要价值在于把愿景拆成可实现的系统、可读的界面和可验证的技术约束。
3. D-04 已撤回；供应商六属性与 12 概念预算均不应因此改动。
4. D-01 不应直接用 A/S 档硬锁委员会模式解决承制支配问题。
5. D-02 应按事项类型定义超时行为，不能把“每周展示一个”误解为“每周只发生一个问题”。
6. E-01 是当前最高优先级的验证基础，但 7,477 工作点和 24.92 周仍是占位蓝图的简单换算，不是正式平衡结论。
7. 上一轮对 pro-rata 和立项一次性现金入账的倾向均已撤回；应先比较完整账务路径和现金流模型。
8. A-03、D-12、D-05、D-13 等建议应优先复用现有概念与数据归档，不增加第 13 个玩家概念。
9. PR #42 / #45 的工程集成状态与愿景评审分开处理；本文件不代表 M1 已验收或代码已合并。

**最终原则：先确定玩家应该做什么选择，再决定系统如何承载；先让生产模型可信，再做经济平衡；先确保每个新增机制改变了玩家的判断或结果，再决定是否值得实现。**
