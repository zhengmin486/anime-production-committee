# 制作蓝图规范（Blueprint Spec）

> 状态：v0.1 内容契约草案；配套样例 [`blueprints/tv_standard.blueprint.json`](../blueprints/tv_standard.blueprint.json)
> 上位文档：[领域架构设计](DOMAIN_ARCHITECTURE.md) §7.3；权威玩法：[DECISION_LOG](../decisions/DECISION_LOG.md) DEC-PROD-001/002/003
> 校验命令：`npm run validate:blueprint`
>
> **为什么先有这份文件**：公共制作 + 单集 + 跨容器依赖 + 交付门槛这套结构，光在架构文档里写字段是无法验证的。蓝图是这套结构唯一的**可检查实例**——能不能实例化、依赖有没有环、门槛是否可达、粒度是否可读，都必须在 M0 用样例 + 校验器证明，否则"契约冻结"只是一张字段清单。

---

## 1. 蓝图是什么，不是什么

| 是 | 不是 |
| --- | --- |
| 一部作品的工作项模板：公共制作项 + 单集项 + 依赖 + 门槛 | 一部具体作品的状态（状态在 Project 里，立项时实例化） |
| 内容配置，可按规模/题材制作多份 | 平衡表（数值仍是 `[PLACEHOLDER]`，由模拟标定） |
| 立项时展开为 N 个单集的依据 | 运行时可变对象（实例化后冻结，改蓝图不影响在制项目） |

一份蓝图只描述**一部作品**。公司可以同时持有多个项目，每个项目用自己的蓝图实例。

## 2. 结构

```json
{
  "schema_version": 1,
  "id": "tv_standard",
  "name": "常规 TV 季番（12 集）",
  "scale": "tv",
  "episode_count": 12,
  "work_unit": "centi_staff_week",
  "common": [ /* 公共制作项 */ ],
  "episode": [ /* 单集模板项 */ ]
}
```

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| `schema_version` | 必须为 `1` | 结构变更时升版，不与存档版本混用 |
| `id` | 小写 snake_case，全局唯一 | 企划通过 `blueprint_id` 引用 |
| `scale` | `ova` / `short` / `tv` / `movie` | 与企划规模一致；不一致直接拒绝 |
| `episode_count` | 正整数 | TV 12–13、短篇 1–4、OVA/剧场版 1（校验器给警告而非错误） |
| `work_unit` | 固定 `centi_staff_week` | **1 工作点 = 1/100 人周**。不声明单位就无法解读 `work_total`，校验器直接报错 |
| `common[]` | 非空 | 项目级公共制作，无阶段 |
| `episode[]` | 非空，六阶段全覆盖 | 单集模板，实例化时复制 N 份 |

### 2.1 工作项字段

| 字段 | 适用 | 约束 |
| --- | --- | --- |
| `key` | 全部 | 小写 snake_case，同容器内唯一；实例化后变成 `ep01.script` 这类 id |
| `name` | 全部 | 展示文案 |
| `stage` | 仅单集项 | 必须是六阶段键之一 |
| `ability` | 全部 | 驱动该工作项的专业能力（六项之一） |
| `work_total` | 全部 | 正整数，单位见 `work_unit` |
| `deliver_at` | 全部 | 1–1000，最低交付门槛占 `work_total` 的千分比 |
| `deps` | 全部 | 依赖 key 数组；跨容器写 `common:<key>` |
| `is_gate` | 仅单集项 | 是否为作品交付门槛项；至少一个，且建议 `deliver_at=1000` |

### 2.2 阶段键（顺序固定）

```text
content_design → storyboard_key_animation → animation
→ art_visual → photography_editing → sound_delivery
```

阶段顺序只用于**分派排序的兜底优先级**与 UI 分组，**不是门禁**。真正的先后关系全部由 `deps` 表达——这是"不采用整部作品串行门禁"的结构保证。

## 3. 依赖与门槛的语义

```text
delivered(item)  ⇔  work_done × 1000 >= deliver_at × work_total
unlocked(item)   ⇔  ∀ dep ∈ deps: delivered(dep)
```

- **门槛解锁，完成不解锁**：A 达到 `deliver_at` 就解锁 B；A 仍可继续做到 100% 只提质量。
- **跨容器**：公共项是单集项的上游（`common:character_design` → `layout`），因此公共制作天然成为整部作品的前置，不需要额外的"公共阶段"。
- **跨单集不允许**：单集之间没有硬依赖。TV 的多集并行靠"每集独立成链"实现，而不是把第 2 集挂到第 1 集后面。
- **门槛项**：作品可交付 = 全部 `is_gate` 项 `delivered`。强制交付时用 `gate_completion_permille` 计算扣罚。

## 4. 校验器检查什么

`npm run validate:blueprint`（默认校验 `docs/blueprints/tv_standard.blueprint.json`）。

| 类别 | 检查 | 级别 |
| --- | --- | --- |
| 结构 | 必填字段、类型、取值范围、key 格式与唯一性 | 错误 |
| 单位 | `work_unit` 必须声明 | 错误 |
| 阶段 | 六阶段必须全部有工作项 | 错误 |
| 门槛 | 至少一个 `is_gate`；门槛项 `deliver_at≠1000` 给警告 | 错误 / 警告 |
| 依赖 | key 可解析、不自指、不重复、公共项不得依赖单集项 | 错误 |
| 图 | 公共图与单集图分别检测环 | 错误 |
| 可达性 | 每个工作项都在某条通往门槛项的链上；公共项必须被引用 | 警告 |
| 量级 | 单集工作量在 1–30 人周之外、公共制作占比 > 30% | 警告 |

校验器**不判定平衡**。它只回答"这份蓝图能不能被安全实例化和推进"。

已用五类人为破坏验证过它确实会报错：成环、删除门槛、悬空依赖、缺阶段、孤立项。

## 5. 样例读数（`tv_standard`，12 集）

```text
单集工作项      14 个   596 点（5.96 人周）
公共制作项       6 个   325 点（3.25 人周）
实例化后       174 个  7477 点（74.8 人周）
公共制作占比            4.3%
关键路径最重链          574 点（5.74 人周，单集内）
```

阶段分布：内容设计 2 项 / 分镜与原画 3 项 / 动画 2 项 / 美术与视觉 2 项 / 摄影与剪辑 2 项 / 声音交付 3 项。

**这张表本身就是设计结论**：单集的关键路径占其总工作量的 96%，说明一集内部几乎没有可并行空间——并行度来自"多集同时推进"和"背景与作画两条线"。如果想让单集内部更并行，正确做法不是把阶段切细，而是增加互不依赖的支线（如背景线与作画线），否则只是把串行链切得更碎。

## 6. M0 必须用这套东西证明什么

| 待证明 | 怎么证 |
| --- | --- |
| 蓝图能实例化为合法项目 | 用样例跑 `start_work`，校验器 + 状态校验双通过 |
| 依赖与门槛语义正确 | 手算：把某集推到 `deliver_at`，确认误报/漏报为零；下游解锁、上游仍可继续 |
| 跨容器依赖成立 | 公共项未达标时，依赖它的单集项不可开工 |
| 门槛与交付一致 | 门槛全集达标后 `deliver_work` 通过；缺一项则拒绝 |
| 粒度可读 | 用 14 项/集跑一集，检查周回执是否还能读懂（这是 H5 的验证） |
| 数量可控 | 12 集实例化后的状态体积与单次推进耗时（H1/H6） |

**当前样例的定位**：结构可检查的**量级样例**，不是平衡定稿。数值、集数、每集项数都会在模拟阶段改；改的是数字，不是结构。

---

## 7. 待定与边界

- 不同规模是否共用同一份阶段模板：当前 `movie`/`ova` 复用 episode 模板、`episode_count=1`，暂不为剧场版单独设计公共制作结构。
- 是否需要"未开工单集"的懒实例化：当前全量实例化（174 项），见架构 §16 的"单集日程"缝。
- 工作项命名与数量是内容工作，需与 WP6 的企划样本对齐。
- 蓝图不承载美术/文案资源，只承载生产结构。
