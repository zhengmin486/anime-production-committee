# 可玩性研究与制作随机性重构提案

状态：2026-11-24 · 讨论记录 / 实验提案，**不是已冻结的正式规则，也不代表已经实现**。

## 1. 问题背景

近期设计投入大量精力调查动画制作业界、制作流程、岗位分工、合同、委员会投资和经营规则，但对「怎样让游戏本身好玩」缺少同等程度的研究。

当前试玩反馈指出一个直接问题：**玩家点击推进下一周之前，基本已经知道下一周会发生什么。** 如果产能、质量、员工状态和成本都能被精确预测，时间推进就只是播放计算结果，玩家缺少期待、意外和临场决策。

因此，后续设计不能只证明机制符合业界现实，还必须验证它是否创造了有趣的选择、风险、惊喜和正反馈。业界真实性是题材可信度的基础，不是可玩性的替代品。

## 2. 本轮设计方向

### 2.1 工作量与质量都引入常规随机波动

每次工作结算同时产生两个相互独立、但都受员工状态和能力影响的结果：

- **工作量结果**：围绕员工当前预期产能产生随机波动。
- **质量结果**：从当前制作阶段允许影响的质量维度中随机抽取若干项，并分别产生随机提升。

工作量高不代表质量必然高；工作量低也不代表质量必然低。两者不能被合并成同一个产出指标。

### 2.2 员工能力采用「C：提高平均表现，同时提高稳定性」

员工能力对随机结果产生双重作用：

1. 能力提高预期表现：平均工作量更高，质量提升的期望值更高。
2. 能力提高稳定性：结果分布更集中，低谷更少；但仍保留发挥失常和超常发挥的可能。

疲劳、士气、专业匹配等状态继续影响表现。具体影响公式、分布形状、倍率范围和概率均待实验，不在本提案中预设为正式参数。

### 2.3 六维作品质量

作品质量拆分为六个独立维度，暂定各维度 0–100 作为实验尺度：

1. 剧情：故事结构、叙事与人物塑造。
2. 演出：镜头设计、节奏、场面调度与表现力。
3. 作画：人物造型、背景和美术表现。
4. 动画：动作设计、动态表现与流畅度。
5. 音乐音效：配乐、音效和声音设计。
6. 后期：剪辑、摄影、合成、色彩及整体完成度。

六项质量分别累积。最终作品评价不应只展示单一总分，还应能呈现作品的突出项与短板。

### 2.4 五个制作阶段与质量维度的初步对应

沿用现有五阶段，不增加第六个制作阶段。以下是质量提升倾向草案，不是排他限制，也不是最终权重：

| 制作阶段 | 主要质量维度 | 次要质量维度 |
| --- | --- | --- |
| 脚本企划 | 剧情 | 演出 |
| 分镜演出 | 演出 | 剧情、作画、动画 |
| 原画作画 | 作画、动画 | 演出 |
| 动画检查 | 动画 | 作画、演出 |
| 后期制作 | 后期、音乐音效 | 演出 |

音乐音效保留为独立维度。现有五阶段没有独立音乐制作阶段，首轮可由后期阶段承载内部贡献，并为外部音乐团队/供应商贡献保留空间；是否需要更细的外部合作规则，后续再验证。

### 2.5 个人贡献归属

每名员工在每次工作时独立结算工作量与质量贡献，再汇总到项目当前阶段和作品。

这样员工能力、专业匹配、人员组合才会体现在作品结果中。汇总规则需要避免重复计入团队整体质量，也要明确临时员工和外包批次如何进入同一口径。

## 3. 每次工作结算的实验流程

1. 根据员工能力、专业匹配、疲劳、士气和当前工作配置计算预期产能。
2. 抽取工作量随机结果；员工能力越高，期望表现越高、波动范围越小。
3. 根据当前制作阶段生成可影响的质量维度池。
4. 结合员工能力与专业匹配，计算维度抽取权重。
5. 随机抽取一个或多个维度，并分别抽取质量提升值。
6. 汇总员工个人贡献，更新阶段进度、作品六维质量和员工状态。

质量提升与工作量波动分别抽取，不将质量增量简单按实际工作量线性绑定。两者仍可通过员工能力、工作类型和阶段规则共享部分影响因素。

## 4. 随机性设计原则

- **有预期，不可精确预知**：玩家可以看到产能区间、质量趋势和风险信号，不应在点击推进前看到下周的精确结果。
- **随机不是惩罚**：常规随机波动主要制造不同局面；显著负面后果应有原因、预警或应对选择。
- **能力有价值但不保证结果**：强员工平均表现更好且更稳定，不等于每周必定高产。
- **随机结果可复现**：继续遵守项目种子与稳定随机消耗顺序；同一初始状态、种子和决策序列应得到相同结果。
- **不破坏规划**：玩家安排人员、策略和资源仍然重要；规划降低风险但不能消灭不确定性。
- **不提前冻结参数**：概率、分布、波动区间、质量权重和边际递减均由实验校准。

## 5. 参考开罗游戏后的启发

本轮讨论以《游戏发展国++》等开罗经营游戏作为体验参考，借鉴方向不是照搬数值或事件表，而是关注：

- 经营推进过程中持续产生可读的反馈。
- 员工与团队配置能影响作品成长。
- 作品在不同维度形成差异，而非只追求单一分数。
- 开发中可能出现意外、提案和临时机会，迫使玩家作出选择。
- 作品完成后的评价与市场反馈能回过头检验玩家此前的经营决策。

随机事件不应变成每周固定弹出的卡牌窗口。常规制作波动、阶段性提案、外部环境变化应承担不同职责，事件的价值在于创造决策，而不是单纯改变数字。

以上是设计启发，不视为对某款参考游戏机制的完整考据；后续可通过实际游玩和资料研究补足证据。

## 6. 下一步实验计划

在独立实验模拟器中使用相同员工、项目规模、阶段设置和排班策略，比较三组：

| 实验组 | 工作量随机 | 质量随机 | 用途 |
| --- | --- | --- | --- |
| A：确定性基线 | 否 | 否 | 作为当前模型对照 |
| B：工作量波动 | 是 | 否 | 观察工期与排班变化 |
| C：双随机 | 是 | 是 | 观察作品差异和经营局面变化 |

重点记录：

- 同样配置下的工期分布、按期完成率和工作量差异。
- 六维质量的均值、方差、组合差异及明显短板比例。
- 高能力员工是否体现出更高平均值和更低波动。
- 不同人员组合是否形成不同作品特色。
- 随机性是否产生值得玩家调整计划的局面，而非只增加噪声。
- 随机机制是否让玩家在推进前有合理判断空间，但不能精确预知结果。

建议先做多种子重复模拟，再用少量实际试玩观察玩家是否会因为结果变化而改变决策。平均分更高不是实验成功标准。

## 7. 可玩性研究补课

后续研究应从「业界如何运作」扩展为「玩家为什么愿意继续玩」：

1. **竞品实际游玩记录**：至少实际体验开罗代表作及若干经营/管理模拟游戏，记录核心循环、决策频率、信息揭示、随机性、成长反馈、失败压力和重玩动力。
2. **机制拆解**：分析每个系统创造了什么选择、风险、期待或反馈；避免只整理设定、数值和功能清单。
3. **玩家体验问题**：每个机制都追问：玩家何时需要做决定？不知道什么？担心什么？期待什么？结果如何反馈？下一轮为何想继续？
4. **原型验证**：先用纸面流程或轻量模拟验证体验，再决定是否进入正式 C++/WASM 核心。
5. **证据分层**：区分实际游玩观察、公开资料、个人推测和团队设计决定；不要把推测写成竞品事实。

每次研究最终应产出「可借鉴机制—它创造的玩家体验—适配本项目的改造—验证方法」，而不是单纯的业界资料摘录。

## 8. 当前未决定事项

以下事项均未冻结：

- 工作量随机分布、波动范围与截断方式。
- 质量维度抽取数量、权重、增量分布。
- 能力、疲劳、士气对均值与稳定性的具体公式。
- 六维质量上限、边际递减与最终综合评价公式。
- 各阶段的精确维度权重。
- 外包、临时员工、音乐团队的贡献合并规则。
- 返修、事故等特殊情况下是否允许质量下降。
- 阶段提案、制作事件和外部环境随机性的触发频率与处理方式。
