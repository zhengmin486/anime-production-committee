## 4. 仓库文档、代码与历史决定之间的差异

1. **分账公式落后于规则**：唯一实现委员会开工与结算的 `46a0b47`（未推送）在 `game_core.cpp:1195` 使用 `scale(revenue, pct*10)` 的**单渠道旧公式**，且把 BD 也按投资比例分了 —— 与 `DATA_MODEL.md:109`、`GAME_RULES.md:543-549/:582-589` 正面冲突。**A**
2. **承制 BD 三层未同步**：`DATA_MODEL.md:51`、`gameV3.ts:542`、`game_core.cpp:480` 都强制承制 `commercial_share_received == 0`；V3.11 §2/V3.12 §3 要求承制同样拿 BD 毛 50%。**A**
3. **商业收入不进现金**：main 的 `calculate_result` 只在 `:1159-1160` 算出 `commercial_score`/`revenue` 并写进 WorkRecord（`:1206`），项目区间内唯一现金变动是逾期罚金（`:1166`）；`profit = contract_received − costs_total`（`:1207`），且记录里 `investment_percent` 被硬编码为 0（`:1203`）。所谓"商业收入"目前纯属账面，与"渠道分账进现金"的规则表述不同层。**A**
4. **委员会路线在 main 上完全走不到**：`:185` 目录 `allowed_modes=["contract"]` → `:875` 模式闸门；`:866` 开工拒绝；`:753` 推进拒绝；`:1154` 结算拒绝；`:951` 延期拒绝。`46a0b47` 的测试靠 `committee_offer_state()` 手改 state 才进得去。**A**
