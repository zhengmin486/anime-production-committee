# 事件应急外包 → Vendor 正式合同链：编排设计准备（#122）

> **状态：设计准备，不是实现契约。** #122 的前置是 #7 的 Vendor 运行时与 5 项裁决。
> 当前 `main` 的 `suppliers` / `contracts` 仍是空聚合，`runtime.hpp` 没有 Vendor 命令。
> 本文只固化**不依赖字段命名的编排顺序、原子边界与用例清单**；所有接口字段一律标 `[待 #7 冻结]`，不提前猜测、不落运行时代码。

## 1. 边界

- 应急外包选项由事件卡描述需求，**不隐式签约**：必须由玩家明确选择该选项，且仍走 #7 的正式 Vendor 合同命令。
- Event 侧只负责：把选项载荷翻译成 Vendor 输入、按序调用、汇总回执、失败整链回滚。
- 供应商内部规则（专业匹配、剩余产能、报价、可靠性、合同生命周期）全部属于 Vendor 域；Event 不复制实现。
- 危机分支已废除，本设计只覆盖公司 `running` 状态下的事件选项。

## 3. 编排顺序（唯一）

```text
1. 守卫        公司 running、目标 pending 存在、选项属于该 pending、项目 producing
2. 需求校验    专业方向 / 工作量 / 截止周 / 报价 / 可靠性 五项输入齐全且合法
3. 供应商选取  由 Vendor 域按专业匹配 + 剩余产能 + 可靠性筛选，返回候选与报价
4. 现金预检    报价 ≤ 当前余额；不足则整链拒绝，不产生合同与流水
5. 合同成立    调用 #7 正式合同命令；同一供应商同周产能不得被重复占用
6. 效果落地    合同产生的制作推进只作用于事件归属项目的工作项
7. 账本与回执  Finance 唯一账本记成本并归因 work_id；回执引用合同 id
8. 移除 pending 只移除目标 (work_id, event_id)，其他项目事件原样保留
```

任一步失败 → 回滚到本周阶段快照：不留部分合同、不扣款、不推进制作、不移除 pending。错误码沿用 #7 / M0 已登记集合；新增错误码必须先过 #53，不在 Event 侧私自定义。

## 4. 用例清单（端到端 fixture）

| 类别 | 必测场景 | 期望 |
| --- | --- | --- |
| 正常链 | 事件选项 → 报价 → 校验 → 合同 → 制作/Finance | 合同成立、成本入账、只移除目标 pending |
| 无产能 | 同供应商同周产能已被占用 | 整链拒绝，合同/流水/制作/pending 状态均不变 |
| 无现金 | 报价高于余额 | `INSUFFICIENT_FUNDS` 语义的原子拒绝（具体码待 #7 确认） |
| 低可靠性 | 候选供应商可靠性低于选项下限 | 不选该供应商；无可时候选则拒绝，不降标准签约 |
| 专业不匹配 | 供应商专业与需求不符 | 不进入合同链 |
| 重复处理 | 同 `(work_id,event_id)` 二次选择同一选项 | 第二次按 NOT_FOUND 拒绝，不重复签合同/扣款 |
| 多项目隔离 | 同周其他项目有 pending | 其他 pending 逐字段不变 |
| 可复现 | 同 seed、同状态、同命令序列重放两次 | 合同选择、现金、回执、state hash 完全一致 |
